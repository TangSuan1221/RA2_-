## 1. 交付物定义（给执行 AI 的边界）

本框架交付的是**一套可被判定的技术规格**，不是一个 UE 项目，也不是一份讲解。判定标准：

> 另一个执行 AI 只读本目录，不读 TLOU 的任何视频、不猜测顽皮狗源码，就能实现出一套
> 「近战槽位 + 上下文处决 + 运动匹配移动 + 弹簧臂镜头」的可玩垂直切片，
> 且第 12 章每一条验收用例都能通过。

因此本目录里**不存在**"参考原作手感微调"这类不可判定的要求。凡是"手感"，一律翻译成毫秒、米、度、权重。

### 1.1 三层适配声明（先读，否则会抄错）

| 你的项目 | 顽皮狗 | 本框架采用的取舍 |
|---|---|---|
| WebGPU + Three.js，浏览器，60fps 目标 | PS4 专属引擎，30fps，定制动画管线 | 单线程 TS 核心 + 纯计算核心（可在 Worker 复跑），全部逻辑自己实现，不依赖引擎托管 |
| 撤离 PvPvE，多路径、可回退、玩家决定时长 | 线性走廊、单向推进、脚本化遭遇 | 战斗竞技场是**动态生成的**（槽位围绕玩家实时求解），不是摆好的 Encounter |
| 近战 + 枪械混合，尸群 + 人类 AI 两套 | 近战与枪战是同一套上下文系统的两个分支 | 同一套 Slot 系统同时服务人类 AI（会绕后、会喊话）与感染者（只会挤进来） |
| 需要可复现的运行时（回放/反作弊/联机预留） | 单机 | 核心计算纯函数 + 固定 60Hz 逻辑步 + 显式 RNG 种子 |

## 2. 证据分级（沿用《TLOU-REA-大地图与关卡规范.md》的 E 级制，扩展一级）

| 等级 | 含义 | 本框架中的用法 |
|---|---|---|
| **E1** | 官方文档 / 源码 / GDC 演讲原文直接给出 | 可直接写进规格，不做二次推导 |
| **E2** | 公开可观测（游戏内行为、逆向工具暴露的结构、社区可验证事实） | 可写进规格，但需在章内标注「E2，允许偏差」 |
| **E3** | 工程估算 / 数值反推 | **必须标 E3 并给校准方法**，禁止当硬规范 |
| **E0** | 传闻、二手转述、"业内都说" | 只在第 01 章出现，用于去伪，不进入任何规格 |

**本文档集里唯一一条 E1 级近战 AI 事实**（来源：TLOU2 程序 Min-Lun Chou，GDC 2021《Melee AI in The Last of Us Part II》，经 GameLook 中文实录转写）：

1. TLOU2 战斗系统建立在 **Uncharted 4** 之上；UC4 的"攻击预警（Attack Tells）"极短，玩家必须靠**先出手打断**来避免受伤；TLOU2 **拉长了预警时间**，把近战提升到与枪战同等地位。
2. 数据层分两块：**Melee Attack**（选哪个近战动作）与 **Melee Moves**（移动到攻击位所需的数据）。
3. 触发前有前置条件判定：NPC 是否"正在做其他动作"、"不在近战范围"等。
4. 上层是 **Melee Behaviors**（比 Melee Attack 高一层）：按角色类型与环境生成各自的**攻击指令表**，并决定接近/保持距离、跑还是走、是否加入战斗。
5. **Strafe Slots**：关卡里预置大量坐标点，位于**以玩家为中心的 16 条延伸线**上；NPC 自动进入这些线的**空隙**；当延伸线被障碍物挡住时，寻路逻辑**跟踪被挡住的线并改变 NPC 位置以避开**；到达槽位的 NPC 执行既定动作；系统会**自行调整槽位**，使地图物件不阻碍其行动。
6. 民居场景因房檐/墙壁/栅栏而复杂化，因此设计了**高位与低位两套近战攻击**：例如玩家在齐腰栅栏处受高位攻击 → 身体后仰、做出近乎坠落的表现。

> **这六条是本框架的地基。** 其余关于"Motion Matching 上千切片、RMSE 取最优"的描述属 E2（Epic 官方文档 + 顽皮狗公开分享），第 04 章据此实现，但**代价函数的具体形式是我们的工程选择，不是原作实现**。

## 3. 术语表（中英对照，全目录统一用词）

| 术语 | 英文（规格中一律用英文标识符） | 定义 |
|---|---|---|
| 槽位 | `Slot` | 以玩家为中心、绑定在一条延伸线上的可站立点，带状态与生命周期 |
| 延伸线 | `StrafeLine` | 从玩家中心发出、等角分布的方向线，槽位分布其上 |
| 槽位仲裁 | `SlotArbitration` | 多个 AI 竞争同一槽位时的授予/拒绝规则 |
| 攻击席位 | `AttackerToken` | 允许"真正扑上来打"的许可，全局上限 2 |
| 槽位劫持 | `SlotHijack` | 环境/连招条件满足时，把槽位上的普通攻击替换为特殊演出 |
| 上下文近战 | `ContextualMelee` | 依据周围几何（墙、桌、窗、栏杆、高度差）选择不同招式的机制 |
| 双极状态机 | `DualStateMachine` | 上半身（Aim/Upper）与下半身（Locomotion/Lower）两套独立状态机 |
| 受击层 | `HitReactionLayer` | 以 Additive 方式叠加、不打断下半身移动的独立动画层 |
| 运动匹配 | `MotionMatching` / `MM` | 用未来轨迹 + 当前姿态特征在动画数据库中检索最优帧 |
| 特征向量 | `FeatureVector` | 查询与数据库条目共用的归一化向量 |
| 惯性化混合 | `Inertialization` | 用速度/加速度衰减代替 crossfade 的姿态切换方法 |
| 相位 | `Phase` | 步态周期内的归一化位置，用于脚步对齐 |
| 程序化 IK | `ProceduralIK` | 射线打点后实时解算的脚/手/头 IK |
| 攻击预警 | `AttackTell` | 从起手到命中之间的可读窗口 |
| 硬直 | `Hitstun` / `Poise` | 受击不可行动时长 / 抗打断值 |
| 处决 | `Execution` | 满足条件时触发的锁定演出 + 高伤害 |
| 最后已知位置 | `LastKnownPosition` / `LKP` | 黑板中的信任度可衰减的玩家位置记忆 |
| 知识传播 | `KnowledgePropagation` | 通过喊话/声音在 AI 队伍内共享 LKP |
| 弹簧臂 | `SpringArm` | 相对枢轴点带阻尼、带碰撞回缩的相机支撑臂 |
| 颤抖 | `Trauma` | 累加式震动强度，按平方映射到位移/旋转 |

## 5. 五条不变量（全框架唯一不可协商的东西）

执行 AI 若为省事违反其中任意一条，即使功能可运行也判为不合格：

| # | 不变量 | 为什么不可协商 |
|---|---|---|
| **I1** | **逻辑步固定 60Hz，渲染插值**。所有伤害判定、槽位仲裁、AI 决策只在固定步内发生。 | 否则命中窗口在 144Hz 显示器上变成 2.4 倍长，战斗手感不可复现、无法回放验证 |
| **I2** | **同时拥有攻击席位的 AI ≤ 2**。任何"某个 AI 从背后直接命中玩家"的路径必须经槽位授予。 | 这是 TLOU 近战"被围而不被群殴"的唯一机械保证；失守则表现为"莫名其妙被打死" |
| **I3** | **攻击预警可读**：从起手到命中的窗口内，玩家至少有一次视觉或听觉提示，且提示早于命中 ≥ `CB-TELL-MARGIN`。 | 这是 UC4→TLOU2 唯一被官方确认的设计改动（E1），也是"公平感"的来源 |
| **I4** | **受击不阻断移动**：受击表现走独立 Additive 层，不得锁死下半身状态机（除击倒/处决）。 | 否则出现"被打一下就定住"，是廉价动作游戏的味道 |
| **I5** | **核心计算纯函数化**：槽位仲裁、代价函数、连招图迁移、伤害结算不得读取 `Date.now()`/`Math.random()`，随机数必须来自传入的 seeded RNG。 | 否则第 12 章的回放式验收测试无法成立 |
