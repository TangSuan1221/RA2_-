## 1. 感知
### 1.1 视觉：三门 + 注意累积
| 门 | 判据 | 常量 |
|---|---|---|
| 距离门 | `d ≤ AI-VIEW-DIST × AI-CROUCH-DIST-MULT`（玩家蹲姿乘 0.65） | `AI-VIEW-DIST` 32 m |
| 角度门 | `|wrapPi(yawTo − selfYaw)| ≤ fov/2`；`alertLevel ≥ 3` 时 110° → 150° | `AI-VIEW-FOV` / `AI-VIEW-FOV-COMBAT` |
| 遮挡门 | 每 tick 至多 **2 条**射线：眼点→玩家视点（`CC-EYE-H` 1.62 / `CC-CROUCH-EYE-H` 0.92）、眼点→胸点 1.58 m | `AI-RAY-BUDGET`（新增） |
```
dt = 1 / AI-PERCEPT-HZ                                          // 166.7 ms
distanceFactor = clamp01(d / AI-VIEW-DIST)
noticeTime = d ≤ 18 ? AI-NOTICE-T                               // 0.35 s
           : d ≥ 22 ? AI-NOTICE-T-FAR                           // 1.10 s
           : lerp(AI-NOTICE-T, AI-NOTICE-T-FAR, (d − 18) / 4)   // AI-NOTICE-BLEND
awareness += dt / noticeTime × (1 − AI-NOTICE-FALLOFF × distanceFactor)
awareness −= AI-NOTICE-DECAY × dt                               // 该 tick 无视线时
awareness ≥ 1 → alertLevel = 3, confidence = 1, targetId = 玩家
// 校准：0 m 每 tick +0.476（3 tick = 500 ms 确认）｜16 m +0.333（3 tick）｜32 m +0.190（6 tick = 1.0 s）
// 20 m 断层（不用 BLEND）：19.9 m 需 0.558 s vs 20.1 m 需 1.76 s（3.2×）→ 玩家感到"隔一条线瞬间变瞎"；FAR 只用于远距复核、禁用于近距；6Hz 量化使确认最坏 +166.7 ms，不违反 I3（I3 只约束"命中前预警"）
```
### 1.2 听觉：不经角度门，但要穿墙衰减
```
walls = countWalls(self.eye, event.pos)                            // 线段与 BVH 求交的表面数 / 2
R_eff = R_base × AI-HEAR-WALL-ATT ^ min(walls, AI-HEAR-WALL-MAX)   // 0.7^min(walls,3)，下限 0.343
d ≤ R_eff → awareness += AI-HEAR-AWARE-BURST × (1 − d / R_eff)；LKP = event.pos, confidence = 0.35, alertLevel = max(alertLevel, 1)
// 校准：BURST 0.55 → 55 m 枪声在 8 m 处给 +0.47 = 两枪确认、单枪只到 suspicious（可复算）
```

| 冲刺 | 14 m | `AI-HEAR-SPRINT` | 4.80 m | 隔楼板仍被听见 |
| 枪声 | 55 m | `AI-HEAR-GUNSHOT` | 18.9 m | E0：GDD §6.1「无消音枪声引发尸潮」的数值接口 |
| 消音枪 | 8 m | `AI-HEAR-SILENCED` | 2.74 m | 同房间才暴露 |

### 1.3 触觉（只对已贴脸情形生效，不给反应窗口）
被撞（相对速度 ≥ `AI-TOUCH-SPD` 0.8 m/s 且胶囊间隔 < 2×`CC-CAP-RADIUS`）／被踩（玩家胶囊底与感染者胶囊顶重叠，仅 `kind==='infected'`）／被 `shove` 类招式命中 → 三者一律 `awareness = 1.0`、`alertLevel = 3`；推人必然惊动是设计意图。
### 1.4 感知节流与错峰（6Hz 摊到 60 帧）
`PERCEPT_DIV = TM-TICK-HZ / AI-PERCEPT-HZ = 60 / 6 = 10`（派生量，不单独登记）。每帧只处理 1/10 的 actor：
```ts
// ai/perception.ts —— 对应 03 §2 阶段 5
const PERCEPT_DIV = TM_TICK_HZ / AI_PERCEPT_HZ;                          // 10
export function perceptionStage(w: World, step: number): void {
  for (const a of w.actors) {
    if (a.ai === undefined) continue;
    if ((step + (a.id % PERCEPT_DIV)) % PERCEPT_DIV !== 0) continue;     // 错峰：每帧只更新 1/10
    senseVisual(a, w); senseAuditive(a, w); senseTouch(a, w);           // 射线 / noise 队列 / 球-球
  }
}
```
| 量 | 值 | 推导 |
|---|---|---|
| 每帧更新 actor 数 | `⌈N / 10⌉`，N=20 → **2** | N × 6 / 60 |
| 单 actor 感知预算 | `AI-PERCEPT-MS-ACTOR` 0.15 ms | 0.3 ms（03 §2 阶段 5）÷ 2 |
| 20 AI 感知总预算 | 0.30 ms/帧 = `TM-BUDGET-LOGIC` 3.5 ms 的 8.6%（禁止每帧全量：射线会放大到 2400 ray/s 且反应与帧率耦合） | — |

### 2.1 字段（`TeamKnowledge` 按 `squadId` 一份，成员视图只读）

| `targetId` | `number \| null` | 视觉确认 | token 申请、`requirements` 朝向 |

| `state` | `idle\|suspicious\|searching\|combat\|lost` | §3.3 | 决策树入口 |
### 2.2 LKP 信任度衰减与三用途
`confidence` 每感知 tick 乘 `AI-LKP-DECAY^(1/AI-PERCEPT-HZ)` = `0.90^(1/6)` = **0.9826 / step**（00 给的是 `/s`，此处按 6Hz 幂折算，ID 语义不变）。
| 用途 | 判据 | 行为 | 时间 / 半径 |
|---|---|---|---|
| U1 直接前往 | `confidence ≥ 0.70` | 直奔 `lastKnownPos`，速度 `AI-APPROACH-RUN` 4.20 m/s | 衰减到 0.70 需 **3.39 s** |
| U2 区域搜索 | `0.25 ≤ confidence < 0.70` | 以 LKP 为心、半径 `AI-LKP-SEARCH-R ×(1−confidence)` 取 seeded 随机点逐个查 | 1.8 → 4.5 m |
| U3 放弃 | `confidence < 0.25` | 清 `targetId`，回 `idle`/巡逻，让出 token | 衰减到 0.25 需 **13.16 s** |
这把"AI 记性"变成可数的秒表：13 s 没再看你，它就真的忘了。玩家能学会这个节拍——这是从 AI 手里夺回主动权的唯一心理入口。
### 2.3 丢失目标后 `AI-GIVEUP-T` = 2.50 s 的搜索梯次
| 段 | 时长 | 动作 | 常量依据 |
|---|---|---|---|
| T1 原地扫视 | **0.80 s** | 原地左右扫视 ±90°；`CC-TURN-AIM` 220 °/s → 180°/220 = 0.82 s 刚好扫完 | `CC-TURN-AIM` |
| T2 沿最后速度方向追 | **1.00 s** | 向 `lastKnownPos + normalize(lastKnownVel) × AI-TRACK-DIST(3 m)` 移动，速度 `AI-TRACK-SPD` 3.00 m/s | 3 m ÷ 1.0 s |
| T3 回到 LKP | **0.70 s** | 走回 `lastKnownPos`，按 U2 半径做一次随机点检查 | `AI-LKP-SEARCH-R` |
`0.80 + 1.00 + 0.70 = 2.50 = AI-GIVEUP-T`：改任一段必须同步改 `AI-GIVEUP-T`（A 组用例校验加和）。实现：`giveUpStage(t) = t < 0.80 ? 'scan' : t < 1.80 ? 'track' : t < AI-GIVEUP-T ? 'return' : 'lost'`（`ai/knowledge.ts`）。
## 3. 喊话传播（Knowledge Propagation）
### 3.1 两条半径必须分清
| 半径 | 常量 | 通道 | 传输内容 | 消费方 |
|---|---|---|---|---|
| 信息共享 | `AI-SHARE-RADIUS` 18 m | 逻辑层黑板（延迟队列） | `lastKnownPos` / `confidence` / `targetId` | 队友 `TeamKnowledge` |
| 声音事件 | `ai_roles.social.shoutRadius`（如 25 m，= `AI-HEAR-WHISTLE`） | `bus` 的 `{t:'shout'}` | 一个**可听目标** | 音效、感染者听觉、玩家信息 |
发起：`confidence` 首次跨过 0.70 且 `alertLevel ≥ 2` 且 `social.canShout === true`；此后每 `AI-SHOUT-REPEAT-T` 3 s 复读（须仍 `state === 'combat'`）。
### 3.2 延迟队列（可被反制）
```ts
// ai/knowledge.ts
interface ShoutMsg { speakerId: number; fromPos: Vec3; dueStep: number;
                     payload: { lkp: Vec3; vel: Vec3; conf: number; targetId: number } }
export function enqueueShout(q: ShoutMsg[], a: Actor, step: number): void {   // 0.40 s = 24 步
  q.push({ speakerId: a.id, fromPos: a.transform.pos, payload: readKnowledge(a), dueStep: step + Math.round(AI_SHARE_DELAY * TM_TICK_HZ) });
}
export function flushShouts(q: ShoutMsg[], w: World, step: number): void {
  for (let i = q.length - 1; i >= 0; i--) {
    const m = q[i]; if (m.dueStep > step) continue;
    const sp = w.actors.find(a => a.id === m.speakerId);
    // 反制：0.4 s 内被击杀、或被硬直打断（"没喊出口"）→ 整条消息丢弃，队友 awareness 增量 = 0
    if (sp === undefined || sp.combat.hp <= 0 || sp.combat.state === 'hitstun') { q.splice(i, 1); continue; }
    for (const r of w.actors) {
      if (r.ai === undefined || r.ai.squadId !== sp.ai.squadId || r.id === sp.id) continue;
      const d = dist(r.transform.pos, m.fromPos); if (d > AI_SHARE_RADIUS) continue;    // 18 m
      receive(r, m.payload, 1 - AI_SHARE_FALLOFF * (d / AI_SHARE_RADIUS));              // conf × 0.5..1.0
    }
    q.splice(i, 1);
  }
}
```
| 反制手段 | 生效条件 | 结果 | 可断言 |
|---|---|---|---|
| 0.4 s 内击杀喊话者 | `AI-SHARE-DELAY` 窗口内 | 全队 `awareness` 增量 = 0 | A4 |
| 0.4 s 内打出硬直 | `hitstun` / `poiseBreak` | 同上（被打断喊话） | A4 |
| 投递时距离 > 18 m | 投递时刻计算 | 该队友不接收（声音事件 25 m 仍可听） | — |### 3.3 群体状态机与阈值
| 状态 | `alertLevel` | 进入条件 | 退出条件 |
|---|---|---|---|
| `idle` | 0 | 初始 / 超时遗忘 | 任一通道 `awareness > AI-ALERT-SUSPICIOUS` |
| `suspicious` | 1 | 听觉/触觉/瞥见但 `awareness < 1` | `awareness ≥ 1` → `combat`；`AI-SUSPICIOUS-T` 3 s 无进展 → `idle` |
| `searching` | 2 | `combat` 中丢失视线 | §2.3 梯次走完 → `lost` |
| `combat` | 3 | `awareness ≥ 1` 或收到 `conf ≥ 0.70` 的喊话 | 视线丢失 → `searching` |

## 4. 槽位生命周期（E1：TLOU 近战 AI 核心）
### 4.1 两套状态，不许混用
03 §4.1 的 `SlotState = 'free'|'reserved'|'engaged'|'blocked'` 是**槽位自身状态**（盘上契约，枚举不得改）。下表的 8 态是**某 AI 对该槽位的持有阶段**，存 `Actor.ai.slotPhase`。
| AI 阶段 | `Slot.state` | 进入条件 | 超时 | 失败回退 |
|---|---|---|---|---|
| `free` | `free` | 无槽位 | — | — |
| `requesting` | `free` | brain 选出候选槽位集 | 1 tick | 回 `free`，`code='noSlot'` |
| `reserved` | `reserved` | `requestSlot` 授予 | `SL-RESERVE-TTL` 1.5 s = 90 步 | 回 `free`，释放槽位 |
| `approaching` | `reserved` | 拿到 `approachToken`（上限 `SL-MAX-APPROACH` 3） | `SL-APPROACH-TTL` 3.0 s | 回 `reserved`，`code='approachFail'` |
| `occupying` | `engaged` | 到位 ±`SL-OCCUPY-TOL` 0.25 m 且朝向误差 ≤ `SL-OCCUPY-ANGLE` 30° | `SL-OCCUPY-TTL` 1.2 s | 回 `approaching`，`code='occupyFail'` |
| `attacking` | `engaged` | 拿到 `attackerToken`（上限 `SL-MAX-ATTACKERS` 2）且 `requirements` 全满足 | 招式时长 | 被打断 → `releasing` |
| `releasing` | `engaged→free` | recovery ≥ `CB-CANCEL-POINT` 或被处决/打断 | 0.8 s | — |
| `cooldown` | `free` | 释放 token | `SL-RELEASE-COOL` 0.80 s | 期满 → `requesting` |

### 4.2 名额被占时该做什么（token 上限 `SL-MAX-ATTACKERS` = 2）
| 优先级 | 处境 | 动作 | 目标 | 约束 |
|---|---|---|---|---|
| P0 | `hp ≤ CB-EXEC-HP-PCT`(0.25) 或 `stagger` | **不参与 token 竞争**（防秒杀连锁） | 后撤 | — |
| P1 | 有空 token 且 `requirements` 可满足 | 申请 token → `attacking` | ring 0 = 1.55 m | `SL-MAX-ATTACKERS` 2 |
| P2 | token 满且 `role==='flanker'` | **包抄**：去 ring 2 侧后 gap | `preferAngleDeg` 140° | `SL-RING-DIST` 3.20 m |
| P3 | token 满且 `role==='attacker'` | **游荡 taunt**：ring 1↔2 游走、保 LOS、`AI-APPROACH-WALK` 1.8 m/s | 不占 token | 每 `SL-UPDATE-HZ` 重评 |
| P4 | 刚失去 token | **后撤到第二环**给持有者让位 | ring 1 = 2.35 m | `SL-RELEASE-COOL` 0.80 s |
| P5 | 有效 gap 全占（>8 AI） | **换线**：申请相邻 gap，横向交错 | ≤ 2×`SL-ANGLE-STEP` = 45° | `SL-ANGLE-STEP` 22.5° |
> `SL-MAX-APPROACH`=3 与 `SL-MAX-ATTACKERS`=2 的差：允许 3 人靠近到 1.55 m，但只有 2 人能出手。第 3 人是"压迫感"的存在，不是"第三刀"的来源——这就是 TLOU 被围而不被群殴的机械结构（I2）。
### 4.3 `buildSlotTable`：16 线 × 3 环 → 障碍剔除 → 8 gap → ≤8 有效槽位
E1 事实：槽位位于**以玩家为中心的 16 条延伸线**上；NPC 自动进入**线的空隙**；延伸线被障碍挡住时寻路逻辑**跟踪被挡的线并改位**；系统**自行调整槽位**使物件不阻碍行动。
```ts
// combat/slot.ts —— 签名与 03 §4.1 逐字一致
export function buildSlotTable(player: Actor, obs: ObstacleQuery,
                               step: number, prev: SlotTable | null): SlotTable {
  const lines: StrafeLine[] = [];
  for (let i = 0; i < SL_LINES; i++) {                             // ① 16 条线（22.5° 等角）
    const ang = player.transform.yaw + i * SL_ANGLE_STEP_RAD;       // ② 障碍剔除：球探针
    const hit = obs.sphereCastTo(player.transform.pos, ang, SL_PROBE_RADIUS, SL_RING_DIST[0]);
    let shifted = 0, effAng = ang, blockedAt = hit ? hit.dist : Infinity;
    while (hit !== null && shifted < SL_BLOCK_SHIFT) {              // ③ 被挡线跟踪改位 ≤3 步 = 67.5°
      shifted += 1;
      effAng = ang + (shifted % 2 === 1 ? +1 : -1) * shifted * SL_ANGLE_STEP_RAD * 0.5;
      if (clear(obs, player.transform.pos, effAng)) { blockedAt = Infinity; break; }
    }
    lines.push({ index: i, angleRad: ang, blockedAt, shiftedBy: shifted, effectiveAngleRad: effAng });
  }
  const gaps = mergeGaps(lines, SL_GAP_MERGE);                      // ④ 每 2 条相邻可用线 → 1 gap（共 8 个）
  const scored = gaps.map(g => ({ g, s: scoreGap(g, player, prev) }))  // ⑤ 每 gap 只留 1 槽位并打分
                     .sort((a, b) => b.s - a.s);                        //    lineBias 前 1.0 / 侧 0.8 / 后 0.55
  const slots = scored.slice(0, SL_MAX_VALID)                       // ⑥ 输出 ≤ SL-MAX-VALID(8)
                      .map(({ g }, k) => toSlot(g, k, player, step));
  // 成本 E3：最坏 48 次 sphereCast（探针 SL-PROBE-RADIUS 0.45、高 1.70）+ 8 次打分
  //          合计 0.2 ms 摊平（03 §2 阶段 7，SL-UPDATE-HZ 4Hz = 每 15 步一次）
  return { version: (prev?.version ?? 0) + 1, playerPos: player.transform.pos,
           playerYaw: player.transform.yaw, lines, slots,
           attackerTokens: prev?.attackerTokens ?? [], approachTokens: prev?.approachTokens ?? [] };
}
```
### 4.4 被物件阻碍时的调整
ring 0 被挡而 ring 1/2 通畅 → **降环**（`ringIndex` +1，保留同一 gap，`SL-RING-DIST`）；整条线被挡 → 在 3 步 = 67.5° 内平移寻找可用角（`SL-BLOCK-SHIFT`）；平移 3 步仍被挡 → **放弃该 slot 并让出 token**（`code='blocked'`，回 `free`）；被可破坏物占据按静态障碍同路径处理，破坏后下一轮自动恢复。
### 4.5 迟滞（防抖动，F5 的唯一解）
`SL-HYSTERESIS`（00）0.35 m 是**槽位几何位移**阈值；换槽决策还需**归一化代价比**阈值，故新增 `SL-HYST-PCT` = 0.35（数值同源、用途不同、不可互换）：持槽 AI 仅在 `newCost < oldCost × (1 − SL-HYST-PCT)`，即**代价改善 > 35%** 时才换槽，否则保留原槽并返回 `reason='hysteresis'`。4Hz 重算 × 无迟滞 = 每秒 4 次抖动。
## 5. Melee Behaviors（E1 三层结构落地）
### 5.1 三层与数据落点
| 层（E1） | 含义 | 本框架落点 |
|---|---|---|
| **Melee Attack** | 选哪个近战动作 | `moveset.json` `actions[]` + `ai_roles.melee.attackTable`（**每角色类型的攻击指令表**，E1） |
| **Melee Moves** | 移动到攻击位所需数据 | §4 槽位 + `rootMotion.maxWarpDist` 1.60 m；超出必须先走接近相 |
| **Melee Behaviors** | 更高层：接近/保持距离、跑还是走、是否加入战斗 | `ai/brain.ts` 决策树 + `ai_roles.melee.approachSpeed / walkSpeed` |
### 5.2 决策树（`SL-UPDATE-HZ` 4Hz 评估一次）
```ts
// ai/brain.ts
export function decide(ai: AiState, w: World, step: number): Intent[] {
  const role = ROLES[ai.roleId];
  // Q1 能否直接攻击 = 在 requirements 内 + 拿到 attackerToken
  if (ai.slotPhase === 'occupying' && inRequirements(ai.target, role)) {
    const act = pickFromTable(role.melee.attackTable, ai, w.rng);       // seeded，§5.3
    return [ai.feintRoll(w.rng) ? feint(act) : attack(act)];           // 假动作 §5.3
  }
  // Q2 否则选 Melee Move（接近相）：跑还是走由 knowledge 决定
  if (ai.knowledge.state === 'combat' && ai.knowledge.confidence >= 0.70) return [approach(ai.slotId, AI_APPROACH_RUN)];    // 4.20
  if (ai.knowledge.state === 'searching') return [approach(ai.slotId, AI_APPROACH_WALK)];                                  // 1.80，不暴露
  return [holdOrFlank(ai)];                       // Q3 否则保持距离 / 包抄 / 游荡（§4.2 P2–P5）
}
```
### 5.3 假动作 `AI-FEINT-CHANCE` = 0.25
| 项 | 值 / 规则 |
|---|---|
| 判定点 | 起手进度 `AI-FEINT-CANCEL-PCT` = 0.40 之前，**每招式只抽一次**（不许每帧抽） |
| 实现 | 只需一次 `tryAdvance` 到 `feint` 分支，不新增状态机 |
| 侧移 | `AI-FEINT-SIDE` 0.90 m ÷ `AI-APPROACH-WALK` 1.8 = 0.5 s，落在 `CB-DODGE-TOTAL` 550 ms 内 |
| 反例 | feint 分支不接侧移 → 玩家看到"抬手又放下"的僵尸抽帧（F5 变体） |
```ts
// 与 03 §4.3 tryAdvance(g, cur, pct, input, ctx) 签名一致
const next = tryAdvance(g, curNode, AI_FEINT_CANCEL_PCT, { kind: 'feint' }, ctx);   // 0.40
if (next !== null) { current = next; slide = sideStep(ai, w.rng); }                 // 必须接侧移
```
### 5.4 攻击确认前摇的人性化（「AI 礼貌」）
| 规则 | 判据 | 实现位置 |
|---|---|---|
| ① 受击硬直中不得被新攻击命中 | `player.combat.hitstun > 0` | `combat/action.ts` active 前置检查 |
| ② 处决动画中不得被打断 | `player.combat.state === 'executing'`，且处决期间 **token 集冻结**（不授予、不释放） | `combat/execution.ts` |
| ③ 翻滚结束后 `AI-POLITE-WINDOW` 200 ms 内不得被新攻击命中 | `step − player.combat.dodgeEndStep < 12` | 同上 |
| ④ 两名持 token AI 的 active 起点至少间隔 `AI-ATTACK-GAP` 250 ms | 仲裁时检查 | `combat/slot.ts` |
> 礼貌窗口只拒绝**新的命中**：不拒绝移动、不拒绝已在 active 窗内的攻击、不给玩家数值奖励。唯一目的：让"翻滚"在数学上真的能救命（否则 `CB-DODGE-IFRAME` 0→200 ms 毫无意义）。
### 5.5 `preferHeight`（E1 高位/低位两套）与 05 章环境探针
`'high'`：玩家脚点高差 `Δh ∈ [CC-STEP-UP, CC-VAULT-MAX]` = [0.45, 1.20] m → 选 `attackTable` 中标 `high` 的项（齐腰栅栏高位下砸）；`'low'`：`|Δh| ≤ CC-STEP-UP` 且前方 0.5–1.2 m 有 `rail/table/ledge` 物件 → 选 `context.replacesTo.ledge_high` 类变体（10 §1 `context`）；`'any'`：表内全量。**硬门槛**：招式自带 `requirements.heightDeltaMax` 0.60 m，超出即该招式不可用，不靠 `preferHeight` 兜底。

## 7. 性能与确定性
### 7.1 AI 预算（20 AI 场景）
`ai.perception` 0.30 ms（阶段 5：每帧 2 actor × 0.15）+ `ai.brain` 0.40 ms（阶段 6：4Hz 摊平）+ `slot.arbitrate` 0.20 ms（阶段 7：4Hz 摊平）= **≤ `AI-BUDGET-MS` 1.5 ms/帧**，占 `TM-BUDGET-LOGIC` 3.5 ms 的 42.9%，余 2.0 ms 给输入/角色/战斗。
### 7.2 远景 / 失焦降频
| LOD | 判据 | 感知 | 决策 | 渲染 |
|---|---|---|---|---|
| L0 近 | d ≤ `AI-LOD-DIST-NEAR` 25 m 且视锥内 | `AI-PERCEPT-HZ` 6 | 4 Hz | 全 |
| L1 远 | 25 < d ≤ `AI-LOD-DIST-FAR` 45 m | `AI-LOD-HZ-FAR` 1 Hz | 1 Hz | 全 |
| L2 视锥外 | 不在 frustum | `AI-LOD-HZ-OFFSCREEN` 0.5 Hz | 0.5 Hz | 剔除 |
| L3 休眠 | d > 45 m 且 `idle`（仍按最后意图外推，上限 `AI-LOD-EXTRAP-T` 2.0 s，超时静止并入 L3） | 0（只响应 `noise`） | 0 | 不提交 draw |
### 7.3 确定性（不变量 I5）
| 要求 | 实现 |
|---|---|
| 唯一随机源 + 分流 | `World.rng`（`core/rng.ts` xorshift128），`ai/*` 禁 `Math.random()` / `Date.now()`（静态扫描项）；每条流 = `xorshift128(seed ^ fnv1a(purpose) ^ actorId)`，`purpose ∈ {percept, feint, slotJitter, searchPick}`，新增消费者不得改变既有流输出 |
| 抽样点 | 只有三处：假动作（每招 1 次）、U2 搜索点（每次换点 1 次）、换槽抖动（每次重算 1 次） |
