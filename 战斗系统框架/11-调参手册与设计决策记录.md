# 战斗系统框架 · 11 调参手册与设计决策记录

- 层：操作层。上游：**00 §4 常量（唯一真值源）/ §5 不变量**、**03 契约签名**、**09 AI 规格**、**10 数据规范**。
- 本章只回答两个问题：**"这个感受该动哪个参数、动多少、动完怎么证明变好了"** 与 **"这个决定当初为什么这么做、反悔要改哪些文件"**。
- 证据：**E1** = GDC 2021 近战 AI 事实（16 线槽位、Melee Attack/Moves/Behaviors 三层、Attack Tells 拉长）；**E3** = 工程判断，全部给校准方法；**E0** = GDD-幸存者裂城 §6/§7 需求。

## 0. 本章定位
| 不是 | 是 |
|---|---|
| "手感再顺一点""打击感再强点" | "`CB-HITSTOP-LIGHT` 60 → 80 ms，步长 20 ms，A/B 后冻帧总时长 +33% 且 TTK 不变" |
| 打开游戏靠感觉拧滑条 | 同一 `tests/inputs/*.json` 输入脚本跑两个参数集，diff 确定性指标 |
| 调完就忘 | 每个参数改动登记进 §2 的爆炸半径表，注明是否重录动画 / 是否改变回放哈希 |
**一条铁律**：任何一个参数改动，若说不出**它影响哪一项可测指标**、**判定阈值是多少**，这个改动不予合入。调参的产物是"参数 + 指标 + 阈值"三件套，不是"感觉对了"。

## 2. 调参优先级阶梯与爆炸半径
### 2.1 L0–L5 阶梯（改动代价由高到低）
| 级 | 内容 | 举例 | 改动代价 |
|---|---|---|---|
| L0 | **不变量与契约**，不许调 | `TM-TICK-HZ` 60、`SL-MAX-ATTACKERS` 2（I2）、`CB-TELL-MARGIN` −80 ms（I3，只允许更早） | 改 = 重做 12 章全部 A/E 组验收 |
| L1 | 需**重录动画/重建数据库** | 招式 `windup/active/recovery`、`moveset.json` 片段时长、`MM-SAMPLE-HZ` 30、`MM-PCA-DIMS` 8 | 重跑 `*.mmdb` 构建脚本 + 重录动作捕捉片段 |
| L2 | 改 JSON、绑定动画片段 | `tellScale`、`reactions.json` 的 `hitstunMs`/`knockbackScale`、`attackTable` 条目 | 只改 `ai_roles.json` / `reactions.json`，无需重导资源 |
| L3 | 纯数值、无资源依赖 | AI 感知（`AI-*`）、槽位环距 `SL-RING-DIST`、LOD 频次 | 改 JSON 即生效，回放哈希会变（预期内） |
| L4 | 表现层，不影响逻辑判定 | `CAM-*`、颤抖、FOV、VFX 强度 | 改完截帧对比即可；**不得**反向影响 `combat/*` |
| L5 | 后期再碰（影响统计与联机） | `MM-W-*` 通道权重微调、AI 概率型参数、`AI-LOD-*` | 需重跑整套回放语料 + 网络延迟补偿复核 |
### 2.2 改动爆炸半径表
| 参数组 | 影响判定 | 需重录动画 | 改变回放哈希 | 影响网络/反作弊 | 验证方式 |
|---|---|---|---|---|---|
| `CB-LIGHT/HEAVY-WINDUP|ACTIVE|RECOVERY` | 命中帧、取消点、TTK | **是** | 是 | 是（帧数据须双方一致） | 12 章 C 组 + A/B diff |
| `CB-HITSTOP-*` | 打击感，不改命中与否 | 否 | 是（时间轴变化） | 否 | 冻帧总时长指标 |
| `CB-KNOCKBACK-BASE` | 位移、被击退距离 | 否 | 是 | 是（位置同步） | 位移指标 |
| `reactions.json` `hitstunMs` | 硬直、处决窗口 | 否 | 是 | 是 | 处决成功率指标 |
| `moveset.json` hitbox | 命中判定 | **是**（与动画对齐） | 是 | 是 | 10 §1 的 9 条校验断言 |
| `slots.json` 全部 | AI 走位、围攻结构 | 否 | 是 | 服务端需同参 | 12 章 A 组 |
| `ai_roles.json` 全部 | AI 行为 | 否 | 是 | 是 | 12 章 A 组 + 回放 |
| `camera_profile.json` / `CAM-*` | 仅表现 | 否 | **否**（逻辑不读相机） | 否 | 截帧对比 + 抖动统计 |
| `MM-W-*` / `MM-KNN` | 姿态选择 | 需重建 KDTree | 是 | 是 | 12 章 B 组代价单调性 |
### 2.3 单次改动的五步流程（缺任一步视为未完成）
| 步 | 动作 | 产物 |
|---|---|---|
| 1 | 把一句话主观描述按 §1 翻译成**一个**候选参数 | 参数 ID + 方向 + 步长 |
| 2 | 查 §2.2 爆炸半径：是否需重录动画 / 重建数据库 | 代价估计（分钟或人日） |
| 3 | 只改这一个参数，跑 §4.1 的 A/B（同脚本、同 `TN-AB-SEED`） | diff 表 |
| 4 | 判定：**预期项显著** + 其余项 ≤ `TN-AB-DIFF-REL` + 哈希变化已声明 | `verdict: PASS/FAIL` |
| 5 | 失败则按步长反向走一格；同一病征连续 3 次改参数都失败 → 问题不在参数，回 §5 查代码原因 | 记录（写进 PR 描述） |
> 第 5 步是本章最重要的一条纪律：绝大多数"调不出来"的手感问题是**顺序错 / 层权重错 / 缺一个阶段**，不是数值不对。数值只能让对的机制更好，不能让错的机制变对。

## 3. 五条手感定律（数值证据 + 反例）
| # | 定律 | 数值证据 | 反例（违反后的可观测现象） |
|---|---|---|---|
| ① | **输入到首帧表现 ≤ 100 ms** | 采样相位最坏 1 步 16.667 ms（`TM-DT`）+ 逻辑 1 步 + `TM-BUDGET-RENDER` 10.0 ms 提交 ≈ **43 ms**，余 57 ms 给动画起势。`CB-INPUT-BUFFER` 120 ms 是"按键提前量"，**不计入延迟** | 把输入缓冲当延迟读：玩家感到按了不动，随后一次冲出两招 |
| ② | **预警 ≥ hurtbox 出现前 80 ms** | `CB-TELL-MARGIN` = −80 ms；轻击 `CB-LIGHT-WINDUP` 260 ms，故 `tell.leadMs ∈ [80, 260]`（10 §moveset 断言） | tell 与 active 同帧开始：玩家可用的反应时间只剩 `CB-LIGHT-ACTIVE` 90 ms < 人类简单反应 ~200 ms → 必然"躲不掉" |
| ③ | **加速时间常数 > 减速时间常数** | 到位：`CC-SPD-JOG` 3.35 ÷ `CC-ACCEL` 14.0 = **239 ms**；停下：3.35 ÷ `CC-DECEL` 22.0 = **152 ms**；比 1.57× | 两者倒置（减速 239 / 加速 152）→ 起步像被弹射、停下像冰面滑行（病征 #8） |
| ④ | **镜头位移一阶连续，不得位置跳变** | `CAM-POS-LERP` 0.18/帧 → 时间常数 τ = 16.667 / (−ln 0.82) ≈ **84 ms**；跳变判据：`|Δp_n − Δp_{n−1}| > CAM-NEAR-MIN` 0.12 m 即违例 | 直接 `pos = target` 或穿墙后瞬移回位 → 一帧位移 >0.12 m，前庭系统判定为"被撞"（病征 #11/#13） |
| ⑤ | **随机只在"结果"层，禁入"预警"层** | 合法：`AI-FEINT-CHANCE` 0.25 决定"这一招是虚招还是实招"，两种都有 ≥80 ms 预警。非法：`tellScale ∈ [0.5, 2]` 随机会让同一招的预警时长每次不同 | 预警层随机 → 玩家无法学会任何节奏，"公平感"崩溃；回放也仍能复现（seeded），但人不可读——**可回放 ≠ 可读** |
> 定律⑤的判据可以写成机器断言：任何进入 `{t:'tell'}` 事件的 `leadMs` 必须等于数据表常量 × `role.tellScale`，**不得含 RNG 输入**（12 章 C 组可静态扫描）。

### 3.1–3.5 每条定律的机器验证（可自动化，不靠人看）
| 定律 | 机器断言 | 失败处理 |
|---|---|---|
| ① | `max(inputToFirstFrameMs) ≤ TN-DIFF-BUDGET`（600 步脚本压 120 次按键，取**最大值**不看均值） | 查动画起势 blend 与 `TM-BUDGET-RENDER`；**禁止**调大 `CB-INPUT-BUFFER` 来"看起来跟上手" |
| ② | 静态扫 `moveset.json`：`tell.leadMs ≥ −CB-TELL-MARGIN`(80) 且 `≤ windupMs`；运行时 `tell` 事件时间戳 ≤ 首个 hurtbox 帧 − 80 ms | 该招式直接拒绝入库（10 §1 既有断言，本章只声明它是定律②的执行体） |
| ③ | `CC-SPD-JOG / CC-ACCEL > CC-SPD-JOG / CC-DECEL`，且比值 ∈ [1.3, 1.8] | 只改 `CC-ACCEL` / `CC-DECEL`；`CC-SPD-JOG` 3.35 同时是 MM 数据库覆盖速度，不许为手感单独改它 |
| ④ | 逐帧 `|Δp_n − Δp_{n−1}| ≤ TN-JUMP-EPS`(0.12 m) | 查 `solveSpringArm` 的回缩是否单帧完成——回缩速度必须受 `CAM-SPRING-K` 14.0 限制，不能直接置位 |
| ⑤ | AST 检查：`leadMs` / `tellScale` 的计算链内不得出现 `rng.*` 调用 | 立即回退；这是 I3 的机器化表达，不接受"偶尔随机一下更有真实感" |

## 4. A/B 与可回放
### 4.1 跑法（同一输入脚本，只差参数集）
```ts
// tests/ab.ts —— 不读 Date.now()、不读 Math.random()（I5）
import { runReplay } from '../src/core/loop';
const script = JSON.parse(readFileSync('tests/inputs/arena_01.json', 'utf8'));
// script = { seed: 0x5EED, steps: 600, intents: [{ step, move, aim, buttons }] }
const A = runReplay(script, loadParams('params/baseline.json'));    // 参数集 A
const B = runReplay(script, loadParams('params/candidate.json'));   // 参数集 B（与 A 只差 1 个参数）
if (A.hash !== B.hash) report('决策序列已改变，逐指标对比');         // 哈希不同是预期，不是错误
for (const k of METRICS) assert(Math.abs(B.m[k] - A.m[k]) / A.m[k] <= TN_AB_DIFF_REL || k === 'hash');
```
### 4.2 指标清单（缺一项就不算做完 A/B）
| 指标 | 定义 | 判定阈值（`TN-AB-DIFF-REL` 3%） |
|---|---|---|
| `stepCount` | 实际逻辑步数（600 步脚本应恒为 600） | **必须相等**，不等即逻辑泄漏 |
| `totalPathLen` | `Σ|Δpos|`（玩家 + 全部 AI），米 | 变化 ≤3% 视为等价；>10% 说明改动过头 |
| `hitCount` | `{t:'hit'}` 事件数（分 attacker=player / ai 两类） | 任一方向变化 >1 次需说明原因 |
| `hitstopMs` | `Σ world.hitstop × TM-DT`，毫秒 | 直接对应该参数效果（如 `CB-HITSTOP-LIGHT` +20ms → 按命中数线性增长） |
| `ttkSteps` | 首次命中的 step → 目标 `hp≤0` 的 step | TTK 变化 >15% 属于玩法级改动，需重新过 §2 |
| `inputToFirstFrameMs` | 按键 step → 首个表现事件的 step（定律①） | **>100 ms 直接失败**，不看均值 |
| `hash` | `decisionLog[0..steps)` 的 FNV-1a | 同参数集两次必相同（I5）；跨参数集不同是预期 |
### 4.3 diff 输出格式（合入 PR 时必须贴这一块）
```
params   CB-HITSTOP-LIGHT 60 → 80 ms        (changed 1)
stepCount          600 → 600            =   ok
totalPathLen    1284.7 → 1289.3 m   +0.36%  ok
hitCount ai→player   9 → 9              =   ok
hitCount player→ai  14 → 14             =   ok
hitstopMs          840 → 1120 ms   +33.3%  EXPECTED (= 14 命中 × 20 ms)
ttkSteps           412 → 412            =   ok
inputToFirstFrame   43 → 43 ms          =   ok (≤ TN-DIFF-BUDGET 100)
hash            0x9a3f → 0x51c2     changed DECLARED
verdict PASS（唯一显著变化为预期项，其余均在 3% 内）
```
**合入条件三条同时满足**：① 预期项按理论值变化（本例 14 命中 × +20 ms = +280 ms，实测 +280 ms）；② 其余项偏差 ≤ `TN-AB-DIFF-REL`；③ 哈希变化已在 PR 里声明并说明原因。任一条不满足即 FAIL。

## 5. 常见病征 → 处方速查（20 条）
| 病征 | 最可能原因 | 处方（参数 / 文件） | 步长 |
|---|---|---|---|
| 滑步 | 动画速度与 `motor.vel` 不匹配 | `MM-MAX-DB-SPEED` 12 不动；改 `CC-SPD-JOG` 或补 jog 段样本 | 0.15 m/s |

| 抖动（目标切换抖） | 锁敌/瞄准辅助锥过宽 | `CAM-AIMASSIST-CONE` 6 → 4° | 1° |
| 卡墙 | 弹簧臂探针小 / 胶囊扫掠未处理台阶 | `CAM-PROBE-R` 0.28 → 0.36；查 `CC-STEP-UP` 0.45 是否生效 | 0.02 m |
| 抢攻（AI 同时出手） | 未实现 `AI-ATTACK-GAP` | `ai/brain.ts` + `combat/slot.ts`，`AI-ATTACK-GAP` 250 ms | 50 ms |
| 群殴（>2 人同时打） | token 计数泄漏 | 非参数：断言 A1；查 `SL-MAX-ATTACKERS` 是否被 role 覆盖 | — |
| 假手感（打得中却没反应） | 冻帧/受击层顺序错 | 查 03 §2 阶段 2–4 跳过表与 I4 | — |
| 穿模（武器穿人） | hitbox 提前于 active | 查 `moveset.json` 与 10 §1 断言（时长偏差 ≤16 ms） | — |

## 6. 设计决策记录（ADR 索引，16 条）
| ADR | 决策 | 放弃的替代方案 | 理由 | 若反悔需改 |
|---|---|---|---|---|
| ADR-01 | 不用刚体物理驱动角色，自研 capsule + motor | Rapier 动力学角色 | 60Hz 固定步可确定性复现（I5）；物理引擎的接触求解不可回放 | `src/character/*`、02 §3、12 章 C 组 |
| ADR-02 | 运动匹配用 PCA + KDTree 检索 | 神经网络动作生成 / 状态机动画 | KDTree 检索是纯函数、毫秒级可预算（`TM-BUDGET-MM-SEARCH` 1.2 ms）、失败可解释 | `src/anim/mm/*`、04 章、构建脚本 |
| ADR-03 | 槽位固定 16 条延伸线 | 任意角连续搜索 / 圆形均分 N 点 | **E1**：原作即 16 条线；固定角度让槽位缓存、迟滞比较与回放哈希都变简单 | `src/combat/slot.ts`、`slots.json` `lines/angleStepDeg` |
| ADR-04 | 伤害走确定性纯函数（输入→输出无副作用） | 事件驱动的伤害回调链 | I5：同一输入序列必须同一结果；回调链的执行顺序不可控 | `src/combat/resolve.ts`、12 章 C/E 组 |
| ADR-05 | 冻帧只冻攻击双方（阶段 2–4 跳过） | 全局时间缩放 | 全局缩放会让 AI 也停住，破坏"其他敌人仍在逼近"的压迫感 | `src/core/loop.ts` 阶段表 |
| ADR-06 | 处决用状态锁定而非无敌 | 处决期间给玩家无敌帧 | 无敌帧会让玩家把处决当"免伤按钮"刷；状态锁定只是禁止第三方**开始**新攻击 | `src/combat/execution.ts`、09 §5.4 |
| ADR-07 | AI 礼貌窗口（硬直/处决/翻滚后 200 ms 不得被新命中） | 完全自由竞争 | 否则 `CB-DODGE-IFRAME` 0→200 ms 无意义，翻滚在数学上救不了命 | `src/ai/brain.ts`、`src/combat/action.ts` |
| ADR-08 | 逻辑 60 Hz 固定步 + 渲染插值 | 变步长物理 | I1：步长变化会让 144Hz 显示器上的命中窗变成 2.4 倍 | `src/core/loop.ts`、全部 12 章验收 |
| ADR-09 | 受击走独立 Additive 层，不锁下半身 | 受击打断移动 | I4：锁下半身是廉价动作游戏味道；也让"边退边挨打"不可能 | `src/anim/layers.ts`、`reactions.json` `lockLowerBody` |
| ADR-10 | 感知 6 Hz 错峰（每帧 1/10 actor） | 每帧全量感知 | 射线 2400/s → 超 `TM-BUDGET-LOGIC`；且反应速度与帧率耦合 | `src/ai/perception.ts`、09 §1.4 |
| ADR-11 | 喊话走 0.4 s 延迟队列且可被击杀反制 | 队伍内瞬时共享 LKP | 瞬时会话让"先杀喊话者"这一战术消失；延迟产生可玩的 0.4 s 窗口 | `src/ai/knowledge.ts`、09 §3.2 |
| ADR-12 | 槽位迟滞用双阈值（0.35 m 几何 + 35% 代价） | 单一距离阈值 | 只有距离阈值时，代价略优的相邻槽位仍会来回跳（4Hz × 2 槽 = 每秒 4 次抽搐） | `src/combat/slot.ts`、09 §4.5 |
| ADR-13 | 感染者不开槽位、另设 `AI-HORDE-ATTACK-MAX` 3 | 感染者复用人类槽位系统 | **E0**（GDD §6.1）：尸群要的是"挤"不是"排队"；共用槽位会让尸群表现像人 | `src/ai/brain.ts`、09 §6 |
| ADR-14 | 相机用弹簧臂 + 阻尼而非直接跟随 | 相机位直接跟枢轴 | 一阶连续（定律④）；直接跟随在穿墙回缩时产生位置跳变 | `src/camera/springarm.ts`、`CAM-*` 常量 |
| ADR-15 | 招式/角色/相机全部数据驱动 JSON | 代码内硬编码招式名与帧数据 | 03 §6：代码里出现硬编码招式名即判不合格；改数值不该重新编译 | `src/data/*`、`moveset.json`/`ai_roles.json` |
| ADR-16 | 逻辑层禁止 import three（目录红线） | 逻辑里直接读 `THREE.Vector3` / mesh | 12 章回放验收必须在 `node` 下裸跑 | `src/core`、`src/combat/slot.ts`、`src/anim/*`、`src/camera/springarm.ts` |
> "反悔需改"这一列就是该决策的**耦合半径**：需要改动文件数 >3 的 ADR 是承重墙，不要为了局部手感去碰它；只改 1 个 JSON 的 ADR 才是可以放手试的。

## 7. 里程碑调参清单（M1–M9）
| 阶段 | 必须已确定的参数（冻结） | 可临时硬编码的参数 | 冻结理由 |
|---|---|---|---|
| M1 骨架 + 数据包 | `TM-TICK-HZ`、`TM-DT`、`CB-INPUT-BUFFER`、`moveset.json` 全部帧数据 | 相机全部 `CAM-*`（先用固定机位） | 帧数据决定动画重录，越晚改代价越大 |
| M2 动画/MM | `MM-SAMPLE-HZ`、`MM-PCA-DIMS`、`MM-KNN`、`MM-BLEND-T` | 玩家移动 `CC-SPD-*` 的临时值 | 需重建 `*.mmdb`，不能反复 |
| M3 移动 | `CC-ACCEL`、`CC-DECEL`、`CC-TURN-*` | AI 全部（AI 尚未接入） | 定律③的比值一旦定下就不该反复 |
| M4 槽位 | `SL-LINES`、`SL-ANGLE-STEP`、`SL-RING-DIST`、`SL-MAX-ATTACKERS`、`SL-HYST-PCT` | `SL-UPDATE-HZ`、`SL-W` 打分权重 | 16 线是 E1 契约；token 上限是 I2 |
| M5 战斗规则 | `CB-LIGHT/HEAVY-*`、`CB-TELL-MARGIN`、`CB-POISE-*`、`reactions.json` 8 条 | `CB-KNOCKBACK-BASE`、`CB-HITSTOP-*` | 预警（I3）与帧数据绑定 |
| M6 AI 感知/黑板 | `AI-PERCEPT-HZ`、`AI-VIEW-*`、`AI-HEAR-*`、`AI-LKP-DECAY`、`AI-SHARE-DELAY` | `AI-LOD-*`、`AI-SUSPICIOUS-T` | 感知参数决定关卡节奏，改动会推翻关卡设计 |
| M7 处决 + 上下文 | `CB-EXEC-*`、`CB-EXEC-STAGGER-WINDOW`、`preferHeight` 表 | `AI-FEINT-CHANCE`、`AI-ATTACK-GAP` | 处决窗口与硬直数据强耦合 |
| M8 相机 | `CAM-ARM-LEN`、`CAM-PIVOT-H`、`CAM-SPRING-K/DAMP`、`CAM-FOV-*` | `CAM-SHAKE-MAX-*`、`CAM-TRAUMA-DECAY` | 弹簧参数决定整机手感基线 |
| M9 打磨 / 回放 | **全部**（冻结，进入 L5 变更流程） | 无 | 任何改动都需重跑 12 章全套 A–E 组 |
> "冻结"的判定标准：M4 之后改 `SL-LINES` 要重跑 12 章 A 组全部用例；M5 之后改任一 `CB-*-WINDUP` 要重录对应动画片段；M9 之后任何改动都走 L5 流程（重跑 600 步回放语料 + 网络延迟补偿复核）。请在里程碑评审时逐行对照本表打勾，不要靠记忆。
