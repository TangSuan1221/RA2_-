## 2. 五条不变量（违反任何一条 = 返工，不是"优化"）

- **I1 逻辑固定 60Hz，渲染插值**。逻辑步不得受渲染帧率影响（掉帧只影响画面）。
- **I2 同时持有攻击 token 的 AI ≤ 2**。**任何** AI 的背后命中都必须来自已持有 token 者。这是"敌人不排队送死"的唯一来源。
- **I3 攻击预警（tell）必须早于命中 ≥ 80ms**，且 tell ≤ 起手段。
- **I4 受击走独立 Additive 层，不锁死下半身**（除击倒/处决）。受击仍能走、能还手。
- **I5 核心计算纯函数化，随机数只能来自传入的 seeded RNG**。禁止 `Math.random()` / `Date.now()` / `performance.now()` 参与逻辑。同一 seed + 同一输入序列 → 逐帧状态哈希相同。

## 6. 六个已知陷阱（这六个会各浪费你 1–2 天，别自己再撞一遍）

1. **槽位不是"玩家周围 16 个固定点"**。16 是**延伸线**数（22.5° 一条）；槽位是线上的**间隙**，4Hz 重算，被障碍挡住时要沿线改位（≤3 步 = 67.5°）。做成固定点 → 敌人排队站同一批坐标。
2. **相机：收缩可以瞬时，伸长必须平滑**。`if (len > allowed) { len = allowed; v = 0 }`，其余交给弹簧（k=14、阻尼比 ζ=0.85，注意是**阻尼比**不是裸阻尼系数 `c = 2ζ√k`）。两边都用弹簧 → 贴墙抽搐；两边都硬钳制 → 离墙瞬间弹 0.8m。
3. **冻帧是 per-actor，不是全局**。给受击双方各设 `actor.combat.hitstopUntil`（轻 60 / 重 100 / 处决 140ms）。全局 `world.hitstop` 会把第三方 AI 和相机一起冻住，1v2 时表现为"世界卡住"。
4. **PCA 只能用于粗筛**。8 维投影空间是跨通道线性变换，**无法施加分通道权重**（轨迹 3.0 vs 姿态 1.0）。正确做法：PCA/KDTree 取 32 个候选 → **回到原始 32 维做加权精算**。代价用"通道内取均值再乘通道权重"，不要全维直接求和（否则维度多的通道会压死别的通道）。
5. **软规则必须有降级通路 + 计数**。"同段内不许跳太近（0.25s）""0.6s 内不许复用同一帧"这类规则，在剧烈转向时会把 32 个候选**全部过滤掉**，导致 `match()` 返回 null。必须做二次检索并记 `stats.fallback`，断言写成"硬违例=0 且软降级 ≤10%"。
6. **断言要检验机制，不要检验直觉**。例："有柱子时槽位应该变少"是错的（柱子只把个别槽位推到外环，不会减少 gap 数）。正确的断言是"所有槽位净空 ≥ 探针半径 + 开阔地全在 0 环 + 有柱时至少 1 个槽位被外推"。

## 9. 卡住时的正确反应（按序尝试）

1. **先跑同步**：`node verify.mjs` + `node tools/check-doc-constants.mjs`，确认红的是新改动还是原有问题。
2. **查常量**：`未登记` 报错说明你发明了 ID 或拼错了（例如把 `CB-KNOCKBACK-BASE` 写成 `CC-`）。
3. **查数据**：`degraded=true` 说明动画库太小（<2000 帧），运动匹配会退化成"永远选中同一段"。
4. **查顺序**：fixedUpdate 的 11 阶段顺序不可调换（输入→意图→移动→战斗→感知→决策→仲裁→动画→层混合→相机→事件）。把槽位仲裁放到动画之后，就会出现"动画和槽位不同步"的鬼畜。
5. 还不行 → **停下报告冲突**，并说清楚"哪两条判据互相矛盾"。不要自己仲裁、不要偷偷降级。

## 10. 明确不要做的事

- 不要试图引入物理引擎驱动角色（Rapier 只允许用于道具/布娃娃）。理由：确定性、回放哈希、预算可控。
- 不要用 `AnimationMixer` 做 locomotion 混合（它只会按权重线性混合关键帧）。蒙太奇内部可选用它，核心混合自己算。
- 不要用行为树库做 AI。槽位是**token 争用**，行为树表达不了；用有限状态机 + 打分。
- 不要用 WebGPU compute 做运动匹配（readback 延迟 ≥1 帧，破坏同一步内完成的确定性），留给以后优化。
- 不要在没跑通 M2 之前做画面。先让胶囊在台阶和坡上不抖。
- 不要在没有 replay 脚本的情况下说"手感对了"。手感必须翻译成毫秒/米/度，并用 A/B 记录证明。

**开始吧。第一步是跑那两条命令，不是写代码。**

| 设计 | 原因 |
|---|---|
| §0 先破除"移植"幻想 | 对方如果以为在迁移源码，会花几天去找不存在的东西；并且会照搬 MontageGraph 的网络回滚 |

| §6 六个陷阱 | 全部来自 `verify-report.md §4` 的**真实 FAIL 记录**，不是推想 |
| §7 数值摘要 | 让提示词在没有文件访问时也能落地，避免"读不到就自由发挥" |
