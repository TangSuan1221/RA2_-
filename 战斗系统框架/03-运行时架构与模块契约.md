## 2. 固定步循环（不变量 I1 的实现）

```ts
// core/loop.ts
export interface FrameStats { logicMs: number; animMs: number; renderMs: number; steps: number; }

export function runLoop(world: World, renderer: Renderer, now: number): FrameStats {
  const dt = 1 / 60;                       // TM-DT
  acc += Math.min(now - last, 0.25);        // 防切后台爆帧
  let steps = 0;
  while (acc >= dt && steps < 3 /* TM-MAX-CATCHUP */) {
    world.fixedUpdate(dt, world.rng);       // 全部判定在这里
    acc -= dt; steps++;
  }
  world.renderUpdate(acc / dt);             // alpha ∈ [0,1) 仅用于插值
  ...
}
```

**`fixedUpdate` 的内部顺序不可调换**（顺序错会引出"打不中/被打中却没反应"类 bug）：

| 序 | 阶段 | 写入 | 读取 | 预算 |
|---|---|---|---|---|
| 1 | `input.tick` 输入缓冲老化、意图生成 | Intent | 设备状态 | 0.1 ms |
| 2 | `character.intent` 期望速度/朝向/状态切换 | Motor 输入 | Intent, 相机 yaw | 0.3 ms |
| 3 | `character.move` 胶囊扫掠移动、台阶/翻越 | Transform | 碰撞世界 | 0.8 ms |
| 4 | `combat.tick` 招式生命周期推进、命中扫掠、伤害结算、冻帧 | HP/Poise/State | 招式表 | 0.6 ms |
| 5 | `ai.perception`（每 10 步执行一次 = 6Hz） | Knowledge | 感知几何 | 0.3 ms（摊平） |
| 6 | `ai.brain` 行为选择 → 槽位申请 | SlotRequest[] | Knowledge | 0.4 ms |
| 7 | `slot.arbitrate`（每 15 步 = 4Hz） | SlotTable | 全部请求 | 0.2 ms（摊平） |
| 8 | `anim.buildQuery` 轨迹采样 → MM 检索（节流 33 ms） | Pose | Transform, Motor | 1.2 ms |
| 9 | `anim.layers` 蒙太奇推进 + 层混合 + IK | 最终 Pose | Pose, IK 目标 | 0.8 ms |
| 10 | `camera.solve`（真实解算在 renderUpdate，逻辑只更新意图） | CameraIntent | 输入 | 0.1 ms |
| 11 | `bus.flush` 音效/特效/VFX 事件出队 | 事件消费者 | — | 0.2 ms |

**冻帧（hitstop）实现：按 actor 局部冻结，不是全局暂停**（08 §6.1 提出的契约修正，本版已采纳）。
命中后只给**受击双方**的 `actor.combat.hitstopUntil` 赋值（轻 60 / 重 100 / 处决 140 ms），各 actor 在阶段 2–4 内自行判断 `step < hitstopUntil` 就跳过自己的推进。
**不要**引入 `world.hitstop` 全局字段：全局冻结会让第三方 AI 与相机的推进一起停住，1v2 时表现为"世界卡住"，且会破坏 E1 回放哈希里其他 actor 的时序。受击方的 Additive 层（I4）照常推进，这才是"受击仍能动"的来源。

| 项 | 旧写法（作废） | 新写法（本版） |
|---|---|---|
| 冻结范围 | `world.hitstop = N` | `actor.combat.hitstopUntil = step + N`（仅双方） |
| 第 2–4 阶段 | 全局跳过 | 每个 actor 自查，命中双方跳过、其余照常 |
| 第 5–11 阶段 | 照常 | 照常（不受影响） |

## 3. 核心数据结构

### 3.1 姿态（SoA，避免 GC 抖动）

```ts
export interface Pose {
  readonly boneCount: number;
  readonly quat: Float32Array;   // boneCount*4，xyz w，与 Skeleton 顺序一致
  readonly trans: Float32Array;  // boneCount*3（根骨含位移）
  readonly scale: Float32Array;  // boneCount*3
}
```

### 3.2 角色

```ts
export interface Actor {
  id: number;
  kind: 'player' | 'humanAI' | 'infected';

  anim: AnimState;                // 当前 MM 选中段、播放时间、层权重

```

### 3.3 世界

```ts
export interface World {
  step: number;
  rng: Rng;                        // I5：唯一随机源

  slots: SlotTable;
```

## 5. WebGPU / Three.js 集成边界

| 层 | 技术 | 说明 |
|---|---|---|
| 渲染器 | `three@0.187.0` 的 `three/webgpu`（`WebGPURenderer`）| `await renderer.init()`；无 WebGPU 时 `forceWebGL` 回退（同名 API），**渲染差异不得影响逻辑** |
| 材质/特效 | TSL（`three/tsl`） | debug 线、血迹粒子、命中火花用节点材质写；不用于 gameplay 判定 |
| 角色蒙皮 | 引擎内建 `SkinnedMesh` + 我们产出的 `Pose` | 每帧把 `Pose` 拷进 `skeleton.boneMatrices` 前的 `Quaternion`/`Vector3`（一次性预分配） |
| 碰撞查询 | `three-mesh-bvh@0.9.18` | 关卡网格构建 BVH，提供 `raycastFirst` / `shapecast`（球扫掠自行封装） |
| 物理 | **不引入刚体引擎驱动角色**（决策见 02 章 §3） | 可选：Rapier 仅用于可破坏物/布娃娃尸体，懒加载 |
| 线程 | 主线程逻辑；MM 检索 M2 起可迁 Worker + `SharedArrayBuffer` | SAB 需 COOP/COEP；**必须保留主线程同步实现作为 fallback** |

## 6. 数据驱动边界

三类数据，全部 JSON/二进制，**代码里不允许出现硬编码招式名**：

| 数据 | 形态 | 谁产出 | 谁消费 |
|---|---|---|---|
| `moveset.json` | 招式定义（帧数据、hitbox 体积、取消关系） | 策划/生成器 | `combat/*` |
| `*.mmdb` | 运动匹配数据库（PCA 投影 + KDTree + 帧元数据） | 构建期 Node 脚本 | `anim/mm/*` |
| `anim/*.bin` | 烘焙后的骨骼关键帧（SoA） | 构建期导出器 | `anim/clip.ts` |

字段级定义见 **10 章**；此处只锁定一条：**二进制头必须是 `MMDB` 魔数 + u32 版本号**，版本不匹配启动即报错，不允许静默降级。

## 7. 与第 12 章验收的衔接

第 12 章每条验收用例都是对上面契约的**黑盒调用**：

- 用例 A 组（槽位）→ 直接调 `buildSlotTable` / `requestSlot`，断言 I2。
- 用例 B 组（动画）→ 直接调 `match`，断言代价单调性与禁选窗口。
- 用例 C 组（战斗）→ 驱动 `combat.tick` 固定步序列，断言命中帧与冻帧。
- 用例 D 组（相机）→ 调 `solveSpringArm` 喂人造障碍，断言不穿模。
- 用例 E 组（回放）→ 用 seeded RNG 跑 600 步，两次结果哈希相同（断言 I5）。

因此：**参考实现/ 目录里的纯 JS 版本就是这些签名的第一实现**，执行 AI 的任务是把它们接进 Three.js 世界并替换为真实数据。
