## 1. 动画素材从哪来

`04 §1` 给了完整的烘焙管线（30Hz 重采样 → 镜像 → 特征 → PCA → KDTree），但没写素材来源。三个可选来源，按"省事 ↔ 可控"排序：

| 来源 | 能拿到什么 | 代价 / 风险 | 适用阶段 |
|---|---|---|---|
| **Mixamo**（免费，Adobe 账号） | idle / walk / jog / run / crouch 全套移动动画；少量近战挥击；FBX/GLB 直接下载 | ①骨骼是 `mixamorig:*` 命名，需重定向到本框架的 `humanoid_20` ②**没有**招式分段标记（windup/active/recovery 要自己按帧标）③同一角色风格统一性一般 | M1–M3 跑通管线 |
| **自录 / 外包动捕**（或手机 ARKit/Rokoko 类方案） | 完全匹配你的招式表与时长 | 最贵最慢；需要标定与清理 | M6 之后打磨 |
| **UE5 Game Animation Sample** | 质量最高的 locomotion 与 motion matching 素材 | ⚠️ **授权限制**：Epic 示例资产通常只允许在 Unreal 项目内使用，用于 Three.js 项目需先确认 EULA；**不要**直接搬进商业项目 | 只作参考，不作依赖 |

### 1.1 硬性导出要求（不满足就别烘焙，后面全白做）

| 要求 | 为什么 |
|---|---|
| **30 fps 导出**，时长与 `public/data/anim/manifest.json` 的 `durationSec` 一致（±1 帧） | `MM-SAMPLE-HZ`=30；`P7` 断言按 `floor(dur*30)+1` 算帧数，对不上直接红 |
| **必须导根运动**（root motion，不是 in-place） | `04 §2` 的轨迹特征与 `05 §2` 的根运动仲裁都依赖它 |
| 骨骼重定向到 `humanoid_20`（20 根骨，名单见 `manifest.skeleton.bones`） | `P8` 断言校验 `hitbox.bone` 是否在骨骼表内 |
| 招式片段要与招式表相位严格对齐：轻击 650ms、重击 990ms、闪避 550ms、招架 450ms、处决 900ms | `P1` 断言（相位和 == 片段时长，±16ms） |
| 移动片段各 40 秒（可循环） | 5 × 1201 = 6005 帧，跨过 `10 §9` 的 6000 帧下限 |

### 1.2 需要哪些片段（与 manifest 一一对应）

| 类别 | 片段 | 时长 | 说明 |
|---|---|---|---|
| 移动 | `idle` `walk` `jog` `sprint` `crouch` | 各 40s | 循环，速度分别 0 / 1.55 / 3.35 / 5.60 / 1.05 m/s |
| 轻击 | `atk_light_01` `atk_light_02` | 各 0.65s | 相位 260+90+300 |
| 上下文变体 | `atk_light_01_wall` `atk_light_01_table` | 各 0.65s | 靠墙/靠桌的替换动画（`06 §4`） |
| 重击 | `atk_heavy_01` | 0.99s | 相位 420+110+460 |
| 闪避 | `dodge_back` | 0.55s | 无敌窗 0–200ms |
| 招架 | `parry_front` | 0.45s | 招架窗 140ms |
| 处决 | `exec_finisher` | 0.90s | 双人锚点对齐（误差 ≤0.15m） |
| 受击 | `add_light_front` `add_stagger_front` | 0.35s / 0.90s | **Additive 层**，不是全身动画 |
| 倒地 | `reaction_knockdown` | 0.50s | 击倒/起身 |

### 1.3 替换接线点（只有两个）

1. **`public/data/anim/manifest.json`** —— 唯一清单。加/删片段只改这里。
2. **`tools/bake-mm.mjs` 的 `readClipFrames(clip)`** —— 唯一读文件的地方。当前实现是**程序化合成姿态**（正弦摆腿 + 根位移），换成真实素材时把这个函数改成读 GLB/FBX 采样即可，**二进制布局与后续 PCA/KDTree/加载流程完全不变**。

```bash
node tools/bake-mm.mjs              # 生成 anim/*.bin + mm.locomotion.mmdb
node tools/bake-mm.mjs --check      # 只验头（magic/version/30Hz/dims/flags bit2/≥6000 帧）
```

> 生成物（`*.bin` / `*.mmdb`，约 4.4 MB）已在 `.gitignore` 里排除：它们是**可再生产物**，不进仓库。
> 仓库里进的是"清单 + 生成器 + 校验器"，这比塞二进制更好审查。

## 2. 三个必须由你拍板的数值（战斗框架不擅自定）

`08 §7` 已明确列出：**武器基础伤害表 / 护甲减伤上限 / 弹药品质系数** 属于玩法数值，战斗系统只提供公式与接口：

```
finalDamage = base × hitGroupMul × (1 − armorReduction) × ammoQualityMul
```

`hitGroupMul` 是框架定死的（头 1.8 / 躯 1.0 / 肢 0.7 / 腿 0.55，见 `CB.PART_MUL`），其余三个由你填。

| # | 待裁决量 | 现状 | 建议初值区间 | 裁决后改哪里 |
|---|---|---|---|---|
| **N1** | **武器基础伤害 `base`**（按武器类别） | GDD 全篇只有定性描述（"重甲不覆盖四肢""击中腿部骨折无法奔跑"），**零数字** | 近战轻击 18–26、重击 32–40、枪械单发 25–45、处决 = 必杀（999 走特殊通道） | 新建 `public/data/damage.json`（草案见 §3），或直接写进你的 GDD 数值章 |
| **N2** | **护甲减伤上限 `armorReduction`** | 框架已定"重甲覆盖躯干、不覆盖四肢"，但**减伤比例没定** | 轻甲 0.15 / 中甲 0.30 / 重甲 0.45，上限 0.55（`applyHit` 里硬钳 0.7） | 同上；注意 `C7` 断言测的是**部位倍率**，与减伤独立 |
| **N3** | **弹药品质系数 `ammoQualityMul`** | 未定义 | 劣 0.85 / 标准 1.00 / 军用 1.15 | 同上 |

**不裁决能不能开工？能。** 参考实现用一组虚构相对值（轻击 22 伤害）跑通了全部 33 条断言——因为断言检验的是**机制**（倍率对不对、冻帧几步、token 是否 ≤2），不是平衡性。
但**不能拿它当可玩数值**：22 × 1.8 = 39.6 只是"倍率逻辑正确"的证明，不是"打三下该死"的设计。

## 3. `damage.json` 草案（裁决后落地，现在可选）

```jsonc
{
  "schemaVersion": 1,
  "weapons": {
    "fist":   { "base": 22, "class": "melee_light",  "ammoQuality": null },
    "pipe":   { "base": 34, "class": "melee_heavy",  "ammoQuality": null },
    "pistol": { "base": 28, "class": "gun_light",    "ammoQuality": "standard" },
    "rifle":  { "base": 41, "class": "gun_heavy",    "ammoQuality": "standard" }
  },
  "armor": {
    "none": 0.00, "light": 0.15, "medium": 0.30, "heavy": 0.45
  },
  "ammoQuality": { "poor": 0.85, "standard": 1.00, "military": 1.15 },
  "coverage": { "torso": ["none","light","medium","heavy"], "limb": ["none"], "head": ["none"] }
}
```

`coverage` 直接对应 GDD 的"重甲不覆盖四肢"——它决定 `armorReduction` 是否参与该次结算（四肢恒为 `none`）。

## 5. 合规提醒（三条，别踩）

1. **Mixamo**：免费商用，但**不要**再分发原始 FBX；作品里使用没问题。重定向后的动画数据属于你的工程资产。
2. **UE Game Animation Sample / Epic 示例资产**：EULA 通常限定"仅在 Unreal 引擎项目内使用"。搬进 Three.js 项目**需要先确认授权**，否则请换 Mixamo 或自录。
3. **自录/外包动捕**：需要演员肖像授权与场地许可；商业化项目建议留档。
