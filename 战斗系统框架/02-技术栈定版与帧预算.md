# 战斗系统框架 · 02 技术栈定版与帧预算
**契约层第 4 份。执行 AI 只能使用本文件列出的依赖与版本；新增依赖必须回到本文件登记。**

---

## 0. 定版原则

1. **逻辑与渲染必须能分离到"逻辑侧不 import three"**（03 §1 红线）。原因不是洁癖：12 章验收用例 A/B/C/E 是**在 node 里跑的无渲染回放**，只有逻辑侧零渲染依赖才能自动化判定。
2. **不引入刚体引擎驱动角色**。角色移动用自建胶囊求解 + BVH 环境查询。理由见 `11 §6` ADR-01：确定性（回放哈希）、可预算（固定步最坏耗时可控）、不背物理引擎的唤醒/休眠不确定性。
3. **运动匹配必须自己实现**，不使用任何动画状态机中间件。理由：需要用 KDTree 直接查数据库，且必须能在 node 下跑（中间件都依赖 DOM）。
4. **渲染只用 WebGPU 主路径 + WebGL2 回退**，均通过 Three.js 的 `WebGPURenderer` 单入口，不写两套材质代码（TSL 编译到两种后端）。
5. **所有版本锁定写入 `package.json` 的精确版本**（不带 `^`），并提交 `pnpm-lock.yaml`。理由：`three` 的 WebGPU 后端在 0.16x–0.18x 之间 API 变动频繁。

## 2. 运行时架构：逻辑 / 渲染 / worker 三段

```
┌───────────────────────── 主线程 ─────────────────────────┐
│  runLoop (03 §2)                                        │
│   fixedUpdate ×N  ── 逻辑侧（纯 TS，零 three 依赖）        │
│        │ Pose(SoA) / CameraIntent / GameEvent[]          │
│        ▼                                                 │
│   interpolate → Three.js 场景图（Skeleton.update）        │
│   WebGPURenderer.render()   ← TSL 材质（只做表现）        │
└──────────────────────────────────────────────────────────┘
              │ SharedArrayBuffer（可选）
              ▼
┌──────────── Worker（离线/半在线） ────────────┐
│  bake-mm.mjs（构建期）：动画 → *.mmdb         │
│  kdtree worker（可选运行期）：批量邻域查询      │
└───────────────────────────────────────────────┘
```

**关键约束**：
- `Pose` 用 SoA `Float32Array`（`quat: f32[n*4]`, `trans: f32[n*3]`），因为它要**每帧从 worker/数据库拷贝到骨架**，AoS 会产生 GC 压力（`03 §3`）。
- 渲染插值只插值**渲染侧**的骨骼阵与相机，逻辑状态不插值（不变量 I1）。
- Worker 只在"数据库 > 20000 帧"或"AI > 20 个"时启用，否则主线程直接算（1.2ms 预算足够）。分界条件在 `04 §8` 给出。

## 3. WebGPU 集成边界（写代码时的四条硬约束）

| 约束 | 具体要求 |
|---|---|
| 入口 | `import { WebGPURenderer } from 'three/webgpu'`；`await renderer.init()` 之后再 `render()`。**不得**用 `three` 主入口的 `WebGLRenderer` 作为主路径 |
| 回退 | `if (!navigator.gpu) forceWebGL = true`；`WebGPURenderer` 支持传 `forceWebGL`，**同一份 TSL 代码**跑 GLSL 后端。回退时把 `TM-BUDGET-RENDER` 从 10.0ms 放宽到 13.0ms（`02 §4.2`），并把阴影降到 1 级 |
| 材质 | 只有**表现层**用 TSL（角色描边、受击闪白、地面水渍、雾）。**逻辑侧不得依赖任何材质状态**；受击闪白由 `GameEvent.hit` 驱动材质 uniform，不反向影响伤害 |
| 计算 | 不使用 WebGPU compute shader 做运动匹配（首版）。理由：数据库只有 6000–60000 帧，CPU KDTree 已够；compute 的 readback 延迟（≥1 帧）会破坏"同一逻辑步内完成检索"的确定性。**留给 M9 之后的优化项** |

## 4. 帧预算（16.667ms 一份，60Hz）

### 4.1 逻辑侧（主线程，`TM-BUDGET-LOGIC` = 3.5ms）

| 子系统 | 预算 | 常量 | 依据 |
|---|---|---|---|
| 输入→意图（阶段 1–2） | 0.10ms | — | 环形缓冲读写，无分配 |
| 胶囊移动 + 碰撞（阶段 3，≤8 actor） | 0.80ms | — | 每 actor 3 次 BVH shapecast + 沿墙滑动 |
| 战斗推进/命中/伤害/冻帧（阶段 4） | 0.60ms | — | 含回溯命中的 OBB 扫掠（≤6 个 hitbox 活跃） |
| AI 感知（阶段 5，6Hz 错峰，≤20 AI） | 0.25ms | `AI-PERCEPT-HZ` | 每帧约 2 个 actor 各 2 条射线 |
| AI 决策 + 槽位申请（阶段 6） | 0.40ms | — | 状态机 + 打分 |
| 槽位仲裁（阶段 7，4Hz） | 0.20ms | `SL-UPDATE-HZ` | 16 线 × 3 环 = 48 候选，纯几何 |
| 动画查询构建 + MM 检索（阶段 8） | **1.20ms** | `TM-BUDGET-MM-SEARCH` | 含 KDTree 粗筛 32 候选 + 全代价精算 |
| 层混合 + IK（阶段 9） | **2.00ms**?? | `TM-BUDGET-ANIM` | 见下方修正 |
| 相机意图（阶段 10） | 0.15ms | — | 弹簧臂 + 4 步遮挡迭代 |
| 事件 flush（阶段 11） | 0.05ms | — | 数组复用 |

> **预算自检**：0.10+0.80+0.60+0.25+0.40+0.20+1.20+0.15+0.05 = **3.75ms**，已超 `TM-BUDGET-LOGIC` 的 3.5ms。**修正**：`TM-BUDGET-ANIM`=2.0ms 是**渲染侧骨骼更新 + IK 解算**（发生在插值之后，属于渲染预算），**不计入逻辑 3.5ms**。逻辑侧预算实际为 **3.75ms**，故 `TM-BUDGET-LOGIC` 应解读为"逻辑侧 ≤3.75ms，含 0.25ms 余量"，或把 AI 感知从 6Hz 降到 5Hz 省 0.05ms。**执行 AI 必须按 3.75ms 实测**，若超限则按 4.3 的降级顺序处理。

### 4.2 渲染侧（`TM-BUDGET-RENDER` = 10.0ms，WebGPU）

| 项 | WebGPU 预算 | WebGL2 回退预算 |
|---|---|---|
| 骨骼更新 + IK 应用（`TM-BUDGET-ANIM`） | 2.00ms | 2.60ms |
| 阴影（1 级 CSM，2048） | 2.20ms | 3.20ms |
| 主几何 + 材质（≤8 角色 + 场景） | 4.60ms | 5.80ms |
| 后处理（描边 + 色差 + 轻 Bloom，TSL） | 1.00ms | 1.20ms |
| 余量 | 0.20ms | 0.20ms |

> 16.667 − 3.75（逻辑）− 10.0（渲染）= **2.92ms 系统余量**：用于 GC、事件、浏览器合成。低于 1.5ms 时必须启动 4.3 降级。

### 4.3 降级顺序（必须按此顺序，不可跳级）

| 级别 | 措施 | 省下 | 副作用 |
|---|---|---|---|
| L1 | 远处 actor（>18m）动画更新降到 30Hz | 0.6ms 渲染 | 极远角色动作略顿 |
| L2 | 运动匹配检索从 30Hz 降到 20Hz（`MM-SEARCH-THROTTLE` 33→50ms） | 0.4ms 逻辑 | 起步略迟 |
| L3 | 阴影 2048→1024，级联 1 级 | 1.1ms | 阴影变软 |
| L4 | 后处理关掉色差与 Bloom，只留描边 | 0.7ms | 表现变平 |
| L5 | AI 感知 6→4Hz，槽位仲裁 4→3Hz | 0.2ms 逻辑 | 敌人反应变迟钝（需重测 tell） |
| L6 | 强制 `forceWebGL=false` 但降到 720p 渲染分辨率（内部 upscale） | 2.0ms+ | 画面糊 |

**L5/L6 是"改变玩感"的降级**，必须记录到 debug overlay，且 12 章验收时**禁用 L5/L6**（验收只允许 L1–L4）。

## 5. 内存与体积预算

| 资源 | 规模估算 | 说明 |
|---|---|---|
| `idle+walk+jog+sprint+crouch` 五组动画 bin（30Hz、24 骨骼） | 5 × 40s × 30 × 24 × 7 float × 4B ≈ **4.0MB** | 若用 15Hz 存储 + 运行时插值可减半，但**采样率必须 30Hz**（`MM-SAMPLE-HZ`），故此值不可压 |
| `*.mmdb`（6000 帧，8 维 PCA） | projected 192KB + KDTree ≈192KB + 索引 ~72KB ≈ **0.46MB** | 每帧 8 float + 树节点 2N |
| 招式/数据 JSON | < 200KB | 单文件 < 50KB 便于 diff |
| three + three-mesh-bvh（gzip） | ≈ 640KB | 首屏关键路径 |
| 总计首屏（gzip） | **≈ 5.4MB** | 超过 8MB 必须做动画分帧流式加载（`04 §1` 的 clip 分片） |

**流式策略**：动画 bin 按 `locomotion tag` 分组，先加载 `idle+walk`，`sprint/crouch` 在 loading 界面后台加载。MMDB 必须**整体加载**（KDTree 不能分片），故它是最小可玩集的一部分。

## 6. 浏览器与设备分级

| 级别 | 判定 | 目标帧 | 允许的降级上限 |
|---|---|---|---|
| A（桌面独显 / Apple Silicon） | WebGPU 可用且 `maxBufferSize ≥ 1GB` | 60fps | L2 |
| B（桌面核显 / 笔记本） | WebGPU 可用 | 60fps | L4 |
| C（Android 高端 / iPad） | WebGPU 可用或 WebGL2 | 60fps | L4 |
| D（低端移动） | 仅 WebGL2 | 30fps 逻辑 60Hz 不变 | L6 允许，但**验收不看 D 级设备** |

**注意**：逻辑固定 60Hz **在 D 级设备上也不变**（不变量 I1）。掉帧只影响渲染，逻辑用累加器追帧（`TM-MAX-CATCHUP`=3 步上限），追不上就丢弃逻辑步并记一次 `overrun`（debug overlay 必须显示，12 章 E 组验收要求 overrun=0）。

## 7. 构建与目录

```
战斗系统框架/参考实现/        ← 纯逻辑实现（node 可跑，无 three）
  package.json               ← three 等依赖在此（仅 render/ 目录用）
  src/core/                  ← 常量、数学、RNG、环形缓冲
  src/combat/                ← slot/combo/resolve/execution
  src/anim/                  ← kdtree/mm/hybrid
  src/camera/                ← springarm
  src/character/             ← motor/capsule/ik
  src/ai/                    ← perceive/blackboard/slotlife
  src/render/                ← 唯一 import three 的目录
  tools/bake-mm.mjs          ← 离线烘焙
  tests/                     ← vitest + 回放用例
  public/data/               ← JSON + mmdb + anim bin
```

**红线（`vitest` 用一条测试强制）**：`src/{core,combat,anim,camera,character,ai}` 下任何文件不得出现 `from 'three'`。测试实现：读目录下所有 `.ts`，正则匹配 `from ['"]three`，命中即 fail。

## 8. 版本升级风险表

| 依赖 | 升级风险 | 处置 |
|---|---|---|
| `three` | WebGPU/TSL API 在小版本间会改（`WebGPURenderer` 构造参数、TSL 函数名） | 锁 0.187.0；升级必须重跑 `12` 章 D 组相机与渲染冒烟测试 |
| `three-mesh-bvh` | 与 three 版本耦合（shapecast 签名） | 锁 0.9.18，与 three 同升级 |
| `rapier3d-compat` | wasm 体积、异步 init | 仅在需要布娃娃时引入，且**必须在 loading 屏 await init**，不得在逻辑步内 await |
| `vite` | worker 语法变动 | 低风险，允许升级 |

## 9. 本章给执行 AI 的检查清单（M0 里程碑交付物）

1. `package.json` 精确版本 + lock 文件；`npm ls three` 显示 0.187.0。
2. `src/render/` 之外零 `three` import（用 §7 的红线测试证明）。
3. `await renderer.init()` + `forceWebGL` 回退分支可切换（提供 URL 参数 `?forceWebgl=1`）。
4. debug overlay 显示：逻辑耗时、渲染耗时、MM 检索耗时、overrun 次数、当前降级级别（13 章细化）。
5. 空场景 + 1 个胶囊 + 官方 `three` 示例 GLTF 角色可跑 60fps（这是 M0 的"Hello 骨架"）。
