# 战斗系统框架 · 13 调试工具与性能验收
**执行 AI 必须先把这一章的工具做出来，再写玩法。理由：本框架的所有验收断言都是"看不见的系统"，没有 overlay 你无法判断是自己的 bug 还是数据的问题。**

---

## 0. 三个工具，一件不能少

| 工具 | 作用 | 交付形态 |
|---|---|---|
| **Debug Overlay** | 实时显示状态 + 3D 可视化层 | `src/debug/overlay.ts`（DOM）+ `src/debug/gizmos.ts`（TSL/线框） |
| **Replay Harness** | 输入脚本录制/回放、逐帧状态哈希、两次 diff | `tests/replay.mjs`（node）+ `src/core/recorder.ts`（运行时） |
| **Frame Profiler** | 分阶段耗时 p50/p99、overrun 计数、降级级别 | overlay 的 PERF 页 + `window.__prof` 导出 |

## 1. Debug Overlay 规格

### 1.1 布局（固定六页，快捷键 `F1`–`F6` 切换，`F0` 关闭）

| 页 | 键 | 内容 |
|---|---|---|
| PERF | F1 | 逻辑/渲染/MM 检索/物理 耗时（当前 + p99）、overrun 次数、降级级别 L0–L6、actor 数、活跃 hitbox 数 |
| SLOT | F2 | 16 条延伸线（世界空间画线，被挡的线画红色）、有效槽位（绿球 + 环号）、token 持有者（黄圈 + 角色 id）、每个 AI 的槽位状态与已等待时间 |
| ANIM | F3 | 每个 actor 的 Lower/Upper/Additive 层权重条、MM 选中片段名 + 帧号 + `cost` 分解（5 通道各自数值）、滑步量（足速−角色速）、`db_degraded` 标志 |
| COMBAT | F4 | 当前招式 id + 相位进度（windup/active/recovery 色条）、活跃 hitbox OBB 线框、回溯缓冲帧数、poise 条、无敌帧剩余、处决 `execLock` 列表 |
| AI | F5 | 视锥（半透明扇形）、感知射线（命中/未命中不同色）、黑板（LKP 位置 + confidence）、alertLevel、喊话队列（入队时间/剩余延迟/speaker 存活） |
| CAMERA | F6 | 弹簧臂长度（desired vs actual）、碰撞命中点、pivot、FOV、trauma、震动方向向量、当前 profile 名 |

### 1.2 硬性要求

1. **零分配**：overlay 更新每帧不得产生新对象（预分配行 DOM，只改 `textContent`；gizmo 用固定容量 buffer）。
2. **可关**：`?debug=0` 时整个 `src/debug/` 不进入 `import` 图（用动态 import 保证 production bundle 不含它）。
3. **可视化的东西必须是真实数据**：槽位 gizmo 必须画 `buildSlotTable` 的**真实输出**，不得画"理想槽位"。这是本条最重要的意义——防止"看起来对"。
4. **单帧可冻结**：`F9` 暂停逻辑（渲染继续），用于逐帧观察；暂停时 overlay 仍可切页。

## 3. Replay Harness 规格

### 3.1 输入脚本格式（`tests/inputs/*.json`）

```jsonc
{
  "seed": 12345,
  "ticks": 900,
  "world": "fixtures/arena_flat.json",
  "entities": { "player": {...}, "ai": [{"role":"veteran","spawn":[0,0,6]}] },
  "inputs": [
    { "tick": 0,   "move": [0,1], "attack": false },
    { "tick": 14,  "attack": true },
    { "tick": 80,  "dodge": true }
  ]
}
```

### 3.2 输出（每 tick 一行，可 diff）

```jsonc
{ "tick": 120, "hash": "9f3a1c2b",
  "player": { "pos":[0.02,0,1.13], "state":"meleeAction", "hp":100, "poise":40 },
  "ai": [ { "id":0, "state":"occupying", "slot":7, "token":true, "lpa":[0,0,2] } ],
  "events": ["hit:0:22", "tell:0"] }
```

- `hash` = 状态量化后（位置 1e-3、角度 1e-3）的 FNV-1a；**必须与浮点误差无关**（量化后再哈希）。
- `--twice` 跑两次并逐 tick `diff`，首个不一致 tick 打印两侧完整状态（12 章 E1）。
- `--fps 30|60|144` 仅改变"每逻辑步的渲染插值次数"，用于证明 E2。

### 3.3 用途

| 用例 | 用法 |
|---|---|
| E1/E2 | `node tests/replay.mjs --seed X --script S --twice` |
| 参数 A/B（11 §4） | 两组 `constants.ts` 各跑同一脚本，`diff` 出首个分歧 tick |
| bug 复现 | 玩家报告的"手感问题"录成脚本，进回归测试集 |

## 4. 性能验收方法（12 章 E4 的判定口径）

### 4.1 参考机器定义（必须在报告里写明实际设备）

| 级别 | 参考配置 |
|---|---|
| B 级（基线） | 桌面核显（如 Intel Iris Xe / Apple M1 8-core GPU）、Windows 11 / macOS、Chrome 最新稳定版、1920×1080、`devicePixelRatio=1` |

### 4.2 测量口径

1. **逻辑耗时**：`performance.now()` 包住整个 `fixedUpdate`（含 11 阶段），每步记录 → 报告 p50/p95/p99/max。
2. **渲染耗时**：`renderer.info` + 两次 `performance.now()` 之间；WebGPU 用 `timestamp-query`（若可用），否则 CPU 侧计时（标注"CPU 侧，偏高"）。
3. **MM 检索耗时**：包住 `match()` 全流程，单独统计。
4. **overrun**：`logicAccumulator > TM-MAX-CATCHUP * DT` 时计数 +1。
5. **判定**：连续跑 **10 分钟（36000 步）**，overrun = 0 且 p99(逻辑) ≤ 3.75ms 才算通过（12 章 E4）。

### 4.3 性能陷阱速查（都是网页端特有的）

| 陷阱 | 症状 | 处置 |
|---|---|---|
| 每帧 `new Vector3()` | GC 峰值 → 周期性卡顿（p99 突刺） | 全部改 SoA / 预分配 scratch（`03 §3` 红线） |
| `Skeleton.update()` 调用 2 次/帧 | 白算一遍骨骼矩阵 | 只在渲染前调用一次；逻辑侧从不调用 |
| 材质变体爆炸（每个角色一份 TSL 材质） | 首次出现角色卡 100ms+ | 共享材质 + `InstancedMesh` 或统一 uniform 数组 |
| shadow map 每帧重绘全场景 | 阴影预算超 3ms | 静态物体 `castShadow` 分层 + 2 帧一次更新 |
| `BufferGeometry` 动态重建（hitbox 可视化） | 每帧 GPU 上传 | 固定容量 `InstancedBufferAttribute` + 只更新 count |
| `JSON.parse` 在热路径 | 首帧卡顿 | 全部数据在 loading 屏解析并 `Object.freeze` |
| `Array.prototype.filter/map` 在 fixedUpdate | 分配 + GC | 改用 `for` 循环 + 预分配数组 + `length=0` 复用 |
| `console.log` 遗留 | 每帧字符串拼接 | production 构建禁用；overlay 用 `textContent` |

## 5. 断言开关与"自证"

1. `assert.ts` 提供 `invariant(cond, code, msg)`：`?strict=1` 时抛错；否则累加计数并在 overlay 显示（**不得静默**）。
2. 每条不变量 I1–I5 在代码里**必须有对应的运行时检查**（不只是测试）：
   - I1：渲染帧内不得调用 `fixedUpdate`（用 `inFixedUpdate` 标志断言）
   - I2：`grantToken` 时断言 `count < SL-MAX-ATTACKERS`
   - I3：招式注册时断言 `tell.leadMs >= 80 && tell.leadMs <= windupMs`
   - I4：受击时断言 `lowerBodyState` 未变（除击倒/处决）
   - I5：`rng` 必须来自 `ctx.rng`（`assert.isSeededRng`）
3. `window.__diag()` 返回一个可序列化的诊断对象（供自动化抓取）：`{ perf, slots, mm, combat, ai, invariants: [{code,count}] }`。
