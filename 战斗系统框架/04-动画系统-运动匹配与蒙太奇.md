## 1. 数据库烘焙管线（`tools/bake-mm.mjs`，离线 Node，禁 import three）
| 阶段 | 输出 | 6000 帧耗时 | 失败即终止 |
|---|---|---|---|
| B1/B2 骨骼烘焙+去首尾无效帧 | `anim/<clip>.bin`（10 §8）+`bones.json` | 4.2 s | 骨骼数与 hitbox 引用不符（10 §0 断言 8）；裁剪后 < 2 帧 |
| B3/B4 30 Hz 重采样+镜像生成 | 30 Hz SoA+重积分 `rootDelta`；帧数翻倍候选集 | 1.6 s | `frameCount ≠ floor(dur×`MM-SAMPLE-HZ`)+1`（10 §0 断言 7）；镜像通道表未覆盖 32 维 |
| B5/B6 特征+归一化+相位 | `f32[frame×32]`、`footPhase` | 2.8 s | 任一分量 `NaN`；归一化分母 ≤ 0 |
| B7 PCA+白化 | `pcaMean`/`pcaBasis`/`projected` | 2.3 s | `pcaDims ≠ `MM-PCA-DIMS`` |
| B8/B9 KDTree+落盘 | `kdTree` 块、`*.mmdb`（10 §7） | 1.2 s | 节点数 = 0 或叶容量 ≠ `MM-KD-LEAF`；magic/版本/`sampleHz` 校验失败 |
**B2 去首尾无效帧**：「无效帧」= 首/末帧处 `‖rootDelta‖/dt < 0.02 m/s` **且**相邻帧骨骼平均四元数夹角 < 0.5°，从两端向内连续剔除，硬保留 ≥ 2 帧。理由：idle→walk 过渡里充数的静止帧在 KDTree 中成为密度异常点，被 `MM-KNN` 反复召回，直接表现为 F1 的「原地蹭」。
**B3 重采样**：`N = floor(duration×MM-SAMPLE-HZ)+1`，第 `i` 帧 `t_i = i/MM-SAMPLE-HZ`；跨源帧时四元数 **slerp**（先半球一致化，`dot<0` 取反）、位置线性插值；源 60 fps 降采样与 24 fps 升采样同一路径，**不做区间平均**（会削平足底接触锐边、抬高相位误差）。`rootDelta` 不可插值，必须**重积分**：`rootDelta_new[i] = Σ rootDelta_src(t ∈ [t_i−1/30, t_i])`，否则总位移漂移。循环段末帧与首帧四元数夹角 < 0.2°。
**B4 镜像规则**：镜像 = 关于局部 YZ 平面（`x→−x`，`R=diag(−1,1,1)`）的反射；**未列出的通道一律不取反**。

| 通道 | 变换 | 依据 |
|---|---|---|
| 轨迹/双足/速度的**局部 x** | 取反 | 反射 |
| 上述通道的 **z 与全部 y** | 不取反 | 前向、高度在反射下不变 |
| 骨骼四元数 | `(x,y,z,w)→(x,−y,−z,w)` | 由 `M'=RMR` 推出：转角不变、转轴取 `(a_x,−a_y,−a_z)`。三项自检：绕 Y（转身）反向 ✓、绕 X（前倾）不变 ✓、绕 Z（侧倾）反向 ✓ |
| 骨骼平移 | `(x,y,z)→(−x,y,z)` | 同反射 |
| `heading=(sin ψ, cos ψ)` | `sin ψ` 取反、`cos ψ` 不变 | 恒等式 |
| `footPhase` 左右两列 | **互换** | 左足镜像成右足 |
| `locomotionTag`、`timeOfFrame`、`clipIdHash` | tag/time 不变；hash 取 `fnv1a(id+"_mirror")` | 10 §0 的 fnv1a 规则 |
仅对标注 `mirrorable: true` 的 walk/jog/sprint/strafe 生成；idle、蒙太奇、反应帧不生成——镜像价值在补**反曲率转向**，静止段镜像与自身重合，只增噪声。
**B5/B6 归一化**：先搭 32 维原始向量 `f`，再逐维除固定分母 `k`。分母是 32 个 f32 常量，硬编码于 `anim/mm/features.ts`，运行期由 `db.normDivisor` 提供，**不接受数据覆盖**，一律由 `MM-MAX-DB-SPEED` 派生；`ψ` 取「朝向相对**速度**方向的带符号夹角」而非「朝向 − 根朝向」，否则 `CC-SPD-AIM-STRAFE` 侧移帧与正面小跑帧在朝向通道退化为同一值。

| 通道 | 维 | 采样点 / 含义 | 归一化分母 `k` |
|---|---|---|---|
| `traj` | 20 | 5 点 `t ∈ {−0.40,−0.20,+0.20,+0.40,+0.67}`（`MM-TRAJ-PAST`/`MM-TRAJ-FUTURE`）×(`pos.x`,`pos.z`,`face.x`,`face.z`) | 坐标 `MM-MAX-DB-SPEED×max(abs(t),0.20)` → **4.80/2.40/2.40/4.80/8.04 m**；face 分量 1 |
| `pose` | 8 | 左右足 ×(`pos.x`,`pos.z`,`vel.x`,`vel.z`)，pos 相对骨盆 | pos `CC-CAP-RADIUS`=0.32 m；vel `MM-MAX-DB-SPEED`=12 m/s |
| `heading` | 2 | `sin ψ`、`cos ψ` | 1（已单位化） |
| `velocity` | 2 | 根速度 `v.x`、`v.z` | `MM-MAX-DB-SPEED`=12 m/s |
| `footPhase` | 2 | 左右足相位，`u8 = round(phase×255)`，分辨率 1/256=0.39%（不进代价，只做 §6 对齐） | — |
| 合计 | **32** | 20+8+2+2 = `mmdb.dims` | — |
**B7 PCA 到 `MM-PCA-DIMS`**：32 维中心化 PCA 取前 8 主成分；累计方差比 < `MM-PCA-VAR-KEEP`（0.95）只告警不阻塞（阻塞会让 6000 帧最小包无法交付）。落盘 `projected` 为**白化坐标** `p=(f−μ)·Bᵀ/sqrt(λ)`，白化后 KDTree 欧氏距离 ≡ 原始空间马氏距离，可直接粗筛。主成分符号取「首个 |载荷|>1e-6 者为正」，保证两次烘焙 `pcaBasis` 逐位一致（服务 I5）。
**B8 KDTree 构建**（10 §7 把该块留成 `u8[?]`，本节只细化内部，不改外层字段顺序）：
```text
node = { u32 splitDim, f32 splitVal, u32 left, u32 right, u32 start, u32 count }  // 24 B
块内：u32 nodeCount | node[nodeCount] | u32[frameCount] leafIndices   # 叶: left=right=0xFFFFFFFF，start/count 指向 leafIndices
BUILD(points, idx[0..n)):  stack=[{s:0,e:n}]
  while stack 非空:
    it=pop(); if it.e-it.s <= MM-KD-LEAF: 写叶(splitDim=0xFFFFFFFF,start=it.s,count=it.e-it.s); continue
    splitDim=argmax_v(variance(points[idx[i]][v], i∈[s,e)))          # 方差最大维
    idx[s..e) 按 points[..][splitDim] 原地 partition（中位数为界）; mid=(s+e)/2
    写内部节点(splitDim, splitVal=points[idx[mid]][splitDim], left/right 待回填); push({s:mid,e}); push({s,e:mid})
  回填 left/right 子下标
```
规模（12000 帧含镜像）：叶 750 + 内部 749 → `nodeCount` 1499 = 36 KB，`leafIndices` 48 KB。
**B9 落盘 `*.mmdb` 逐字段写入方**（偏移顺序严格按 10 §7）：

| 8/12/16/20/24 | `frameCount`/`dims`/`pcaDims`/`sampleHz`/`clipCount` | B4/B5/B7/B3/B4 | 含镜像总帧数 / `32` / `MM-PCA-DIMS`=8 / `MM-SAMPLE-HZ`=30 / 含 `_mirror` |
| 28 | `clipTable` | B4 | `{u32 hash, u32 startFrame, u32 frameCount, f32 durationSec}` |
| … | `pcaMean f32[32]`、`pcaBasis f32[32×8]`、`projected f32[frameCount×8]` | B7 | 均值；行主序基；白化坐标（KDTree 建在此） |
| … | `kdTree` | B8 | 上一节块 |

## 2. 特征向量与代价函数
**B5 的维度表即 §2.1 的精确维度表**（32 维 = `mmdb.dims`，局部系 x 右 / z 前），此处不重列。**代价公式**（`w` 取 00 §4.3：`MM-W-TRAJ`=3.0、`MM-W-POSE`=1.0、`MM-W-HEADING`=1.5、`MM-W-VELOCITY`=2.0；`Σw`=7.5 即归一化特征下 cost 上界；`MM-CONTINUING-BIAS`=−0.05 只加在 continuation 候选上，见 §3）：
```text
cost(q,d) = Σ_{c∈{traj,pose,heading,velocity}} w_c · (1/D_c) · Σ_{i∈c} (q_i − d_i)²      D_c = (20, 8, 2, 2)
```
**为什么用「通道内均值再乘权重」而不是全维直接求和**——设四通道每维误差都是 0.01：

| 口径 | traj | pose | heading | vel | 合计 | 姿态通道实际占比 |
|---|---|---|---|---|---|---|
| **通道内均值（本章）** | 3.0×0.01=0.030 | 1.0×0.01=0.010 | 1.5×0.01=0.015 | 2.0×0.01=0.020 | 0.075 | **13.3%**，等于名义权重占比 |
| 全维直接求和 | 3.0×20×0.01=0.600 | 1.0×8×0.01=0.080 | 1.5×2×0.01=0.030 | 2.0×2×0.01=0.040 | 0.750 | **10.7%**；轨迹点 5→7 时降到 8.9% |
三条可判定后果：① **维度数不污染权重**——`MM-W-POSE` 写 1.0 就是 1.0 的效力，不会因轨迹点多 20/8=2.5 倍被压死；② **改采样配置不改手感**——未来点由 3 减到 2 个只需重调 `MM-W-TRAJ`，其余三个不动；③ **`MM-CONTINUING-BIAS` 可比**——cost 量纲被 `Σw`=7.5 钉住，−0.05 才是固定相对折扣（全维求和口径下同一 −0.05 在 5 点配置相当 13% 折扣、7 点配置相当 9%）。标定要求：稳态小跑实测 cost 中位数必须落在 **[0.10, 0.50]**，超出则调 `MM-W-*` 回区间，**不得改 `MM-CONTINUING-BIAS`**。调参顺序固定：`MM-W-VELOCITY`→`MM-W-TRAJ`→`MM-W-HEADING`→`MM-W-POSE`，最后才动 `MM-CONTINUING-BIAS`。

| 常量 | 值 | 调大 | 调小 | 判定断言 |
|---|---|---|---|---|
| `MM-W-TRAJ` | 3.0 | 急停/急转更跟手，但易选到速度突变帧 → 抖动率↑ | 平滑但停不住，jog→静止位移 +0.3 m | §9 A5、A3 |
| `MM-W-POSE` | 1.0 | 步态连续，跨步稳定 | 同段内姿态跳变、足位穿模 | §9 A3、A6 |
| `MM-W-HEADING` | 1.5 | 转身跟随快，但膝弹跳率↑ | 转向滞后 > 120 ms | §9 A3 |
| `MM-W-VELOCITY` | 2.0 | 打滑更少（速度优先） | 滑移 > `MM-SLIP-TOL` | §9 A3、§6.2 |
| `MM-CONTINUING-BIAS` | −0.05 | 更负 → 更黏当前段，抖动少但响应慢 | 趋 0 → 响应快但 F1 超阈 | §9 A5 |
## 3. 检索流程与停机条件
**流水**：S1 强制重搜判定（§3.3 任一条件成立，绕过节流）→ S2 节流（距上次检索 < `MM-SEARCH-THROTTLE` 33 ms 则复用上次结果、`frame` 按 `dt` 推进，只推进不检索）→ S3 拼装 32 维+归一化+PCA 白化 32→8（0.042 ms）→ S4 KDTree 取 `MM-KNN`=32 候选（`locomotionTag` 位掩码剪枝，0.075 ms）→ S5 过约束+全代价精算+加 `MM-CONTINUING-BIAS`+取最小（0.053 ms）。签名同 03 §4.2 不得改名；`RecentHistory = {lastClipId, lastFrame, lastSearchMs, banned:{frame,untilMs}[], hitFlags, stance}`。
```ts
export function match(query: MMQuery, db: MotionDB, settings: MMSettings,
                     continuing: MatchResult | null, recent: RecentHistory): MatchResult {
  const now = db.nowMs;                                        // 逻辑步时间，非 Date.now()（I5）
  if (!mustResearch(query, db, continuing, recent, now)         // S1
      && now - recent.lastSearchMs < settings.searchThrottle)   // S2
    return advance(continuing, db);                             // 只推进 frame += dt×MM-SAMPLE-HZ
  const q32  = normalizeFeatures(buildFeatures(query), db.normDivisor);          // S3 f32[32]
  const q8   = project(db, q32);                                                // 白化 f32[8]
  const cand = db.tree.knn(q8, settings.knn, db.tagMask(query.locomotionTag));   // S4
  let best: MatchResult | null = null, searched = 0;                             // S5
  for (const f of cand) {
    const banned  = recent.banned.some(b => b.frame === f && now < b.untilMs);   // MM-RESELECT-T
    const tooNear = continuing !== null && db.clipOf[f] === continuing.clipId
                 && Math.abs(db.timeOf[f] - continuing.time) < settings.poseJumpT; // MM-POSE-JUMP-T
    if (banned || tooNear) continue;
    searched++;
    let c = channelCost(q32, db.raw[f]);                        // §2，原始 32 维分通道
    if (continuing !== null && isContinuation(f, continuing, db))
      c += settings.continuingBias;                             // MM-CONTINUING-BIAS
    if (best === null || c < best.cost)
      best = { clipId: db.clipOf[f], frame: f, time: db.timeOf[f], cost: c, searched: 0 };
  }
  if (best === null) return advance(continuing, db);            // 全被否决 → 维持当前段
  best.searched = searched; return best;
}
```
**选中即登记**：每次返回的 `frame` 写入 `recent.banned`，`untilMs = now + MM-RESELECT-T×1000`（+600 ms）；队列用定长环形缓冲淘汰，不分配。
**何时强制重搜**（每条都必须绕过节流）：

| 条件 | 判定式 | 为什么必须绕过节流 |
|---|---|---|
| `locomotionTag` 变化 | `query.locomotionTag ≠ db.tagOfFrame[recent.lastFrame]` | 跨步态组，PCA 邻域内无该速度的正确帧 |
| 根速度突变 | `‖v_t − v_{t−1}‖ > MM-RESEARCH-DV`（2.0 m/s） | 33 ms 节流内滑移已超 `MM-SLIP-TOL`（F2/F3） |
| 受击/击飞/击倒 | `recent.hitFlags !== 0` | 下段进踉跄或落地，原段不再合法 |
| 进入锁定（grab/execution） | 该 actor 在 `world.lockedPair` 中 | 蒙太奇接管，MM 让位 |
| 当前段将播完 | `continuing.time ≥ clipDuration − MM-BLEND-T` | 否则停在末帧不前进 |
| 站姿切换 / 代价劣化 | `recent.stance` 翻转（站/蹲/瞄准）；或 `continuing.cost > MM-RESEARCH-COST`（0.30，≈ 中位 cost 上限 0.50 的 60%） | 姿态通道整体跳变、邻域失效；或当前段已劣化 |
| 无历史 | `recent.lastClipId < 0` | 首帧 |
## 4. 惯性化混合
**四元数偏移衰减**：切换瞬间逐骨骼取世界旋转偏移 `q_off(0) = q_prev · q_cur(0)⁻¹`（先半球一致化），按指数核衰减后叠回新姿态：
```text
τ        = MM-BLEND-T / 3 = 0.18/3 = 0.060 s
w(t)     = exp(−t / τ)
q_out(t) = slerp(identity, q_off(0), w(t)) · q_cur(t)
```
三处可判定收尾：`t=0` 残余 100%（输出逐位等于 `q_prev`，切换无跳变）；`t=MM-BLEND-T`（0.18 s）残余 `e⁻³`=**4.98%**；`t=1.5×MM-BLEND-T`（0.27 s）残余 `e⁻⁴·⁵`=**1.11%**，此后按 0 处理并释放缓存。位置沿用同核衰减位移偏移 `p_off = p_prev − p_cur`，但**根骨位移偏移恒置 0**——根位移只允许来自新段 `rootDelta`。实现落在 `anim/inertial.ts` 的 `beginInertial(prev, cur, out)` 与 `applyInertial(off, cur, out, dt)`，二者只读写 `Pose`（03 §3.1）。

| 项 | crossfade（权重插值） | 惯性化（偏移衰减） |
|---|---|---|
| 输出帧来源 / 首帧连续 | 两段顶点插值，**中间帧不属于任何片段**；α=0 时等于旧段 | 恒为「新段真实帧+一次性偏移」，`t>MM-BLEND-T` 后逐位等于库帧；`w(0)=1` 时等于旧段 |
| 足底接触速度 | `(1−α)v₁+αv₂`，同脚反向切换在 α=0.5 处降为 0 → **冻结**（脚在冰上滑） | 保持新段真实值 → **无冻结** |
| 根位移 | 两段 `rootDelta` 加权求和；`CC-SPD-JOG` 3.35 m/s 反向切换在 0.18 s 内位移误差达 **0.60 m** → **漂移** | 位移只取新段 `rootDelta`，误差恒 0 |
| 与代价函数一致 | 混合帧不在库内，下次 query 的姿态特征是假姿态，代价失真 | 姿态恒真，代价假设成立 |
| 适用范围 | 仅非库驱动过渡（idle↔aim 的上身权重） | 所有 MM 选帧切换（本章默认） |
`moveset.json` 的 `anim.blendInMs`/`blendOutMs`（10 §1）只覆盖蒙太奇进出层栈，不改 MM 段间切换。
## 5. 层栈与蒙太奇
**5.1 四层权重合成**——三条硬规则：权重**不归一化**（增量层是叠加不是插值）；根骨位移一律取 Lower；`w_L` 不是可调参数，任何事件不得改写。

| 层 | 驱动源 | 掩码 `m(b)` | 权重 | 合成位 |
|---|---|---|---|---|
| Lower（Locomotion） | `match()` 帧流 | 全骨骼；脊柱以下恒 1 | `w_L = 1.0`（常量） | 基底 |
| Upper（Aim/Attack） | 蒙太奇播放器 / Aim Pose | `spine_01`=0、`spine_02`=0.5、`spine_03`↑=1（feather 区） | `w_U ∈ [0,1]` | 双极 slerp |
| Additive（呼吸/前倾） | 程序化 | 脊柱链+双臂 | `w_A ∈ [0,0.6]` | 增量 ⊗ |
| HitReaction（受击） | `reactions.json` | `spine_02` 以上+头 | `w_H ∈ [0,1]` | 增量 ⊗（最后） |
```text
q_base(b)  = slerp( q_L(b), q_U(b), w_U · m_U(b) )
q_final(b) = q_base(b) ⊗ exp( w_A·m_A(b)·log q_A(b) ) ⊗ exp( w_H·m_H(b)·log q_H(b) )
p_final(b) = p_L(b) + w_U · m_U(b) · ( p_U(b) − p_L(b) )
```
**5.2 蒙太奇分段与 10 §1 `phases` 对齐**：`pct_total = t/(windupMs+activeMs+recoveryMs)`，段时长取 00 §4.5（light 260/90/300=650 ms，heavy 420/110/460=990 ms，不重列）。

| 段 | light 区间 | heavy 区间 | 播放器行为 |
|---|---|---|---|
| windup | `[0,0.400)` = `[0,260) ms` | `[0,0.424)` = `[0,420) ms` | `w_U` 0→1（时长 `anim.blendInMs`） |
| active | `[0.400,0.538)` = `[260,350) ms` | `[0.424,0.535)` = `[420,530) ms` | hitbox 扫掠（08 章），`w_U=1` |
| recovery | `[0.538,1.0]` = `[350,650] ms` | `[0.535,1.0]` = `[530,990] ms` | `w_U`→0，取消窗在此段 |
**5.3 notify 触发**（来源 `anim/<clip>.bin` 尾段 `notifyTable`，10 §8；逐条映射 03 §4.5 事件）：

| notify | 时刻 | 消费方 | 产出 |
|---|---|---|---|
| `tell_start` | `t=0` | `bus` | `{t:'tell', actorId, actionId, leadMs}`（I3） |
| `hitbox_on`/`hitbox_off` | active 两端（0.400/0.538 与 0.424/0.535） | `combat/hitbox.ts` | 开/关扫掠 |
| `footstep` | 片段自带 `time` | `bus` | `{t:'noise', kind:'step', radius:`AI-HEAR-WALK`/`AI-HEAR-SPRINT`}` |
| `cancel_open` | recovery 进度达 `CB-CANCEL-POINT` | `combat/combo.ts` | 打开取消窗 |
| `poseNotify` | 任意 | `bus` | `{t:'poseNotify', name, frame}` |
**时间量化**：蒙太奇按 `MM-SAMPLE-HZ`=30 推进（单帧 33.3 ms），10 §0 断言 1 允许偏差 16 ms < 半周期，故 notify 必须在相邻两采样帧间**线性插值判过零点**触发；整帧对齐会引入 +33 ms 系统性迟到，吃掉 I3 的 `CB-TELL-MARGIN`（−80 ms）余量。
**5.4 取消窗**：取消用收招段内进度 `pct_cancel = (t − (windupMs+activeMs)) / recoveryMs`，`允许取消 ⇔ pct_cancel ≥ CB-CANCEL-POINT`（0.60）；换算到 total 轴为 light `pct_total ≥ 0.815`（530 ms）、heavy `≥ 0.814`（806 ms）。10 §1 的 `cancel.into[].fromPct` 定义在同一 `pct_cancel` 轴（10 §0 断言 4）；据此 10 §1 示例 `dodge_back` 的 `fromPct: 0.50` 必须补 `"allowEarly": true`，否则校验器按断言 4 报错——这是跨章一致性检查点，不是本章放宽条件。
**5.5 不变量 I4 在层栈里的落点**：

## 6. 相位同步与脚步对齐
**6.1 相位提取**（仅烘焙期；运行期只读 `footPhase`）：足部高度过零法 = `h_ankle(t)` 由上向下穿越 `h_contact+0.02 m` 且持续 ≥ 2 帧（平地准，蹲行/上下坡因 `h_contact` 漂移失效）；相对速度法 = `‖v_foot.xz − v_root.xz‖ < 0.35 m/s` 且 `h_ankle < 0.04 m`（对坡度鲁棒，快速摆腿可能误触发）。两法不一致**取速度法**。`phase = (t−t_contact)/(t_contact − t_contact_prev)`；左右足相位差必须 0.5±0.05，否则标 `phaseUnreliable` 并在查询时跳过相位对齐项。
**6.2 相位错误导致的滑步量估算**：`滑步/支撑相 = |v_world − r·v_clip| × T_stance`。jog 基线：步幅 1.35 m、`v`=`CC-SPD-JOG` 3.35 m/s → `T_cycle`=2×1.35/3.35=0.806 s，支撑相占比 0.42 → `T_stance`=0.339 s。

| 场景 | `v_world` | `v_clip` | `r` | 滑步/支撑相 | 判定 |
|---|---|---|---|---|---|
| idle 帧被复用于已起步角色 | 3.35 | 0.00 | 1.00 | 1.14 m | 不可接受 → 由 §3.3「根速度突变」重搜消除（F3） |
| 减速到 2.80 | 2.80 | 3.35 | 0.836→clamp 0.88 | 0.050 m | 可接受 |
| 加速到 3.60 | 3.60 | 3.35 | 1.07 | 0.006 m | 可接受 |
| 长按加速到 4.20 | 4.20 | 3.35 | 1.254→clamp 1.12 | 0.039 m | 可接受，但持续 > 0.3 s 必须重搜到 sprint 组 |
`MM-SLIP-TOL`=0.06 m ≈ 脚长 0.26 m 的 23%（E3，取「视觉可辨」阈下侧）。
**6.3 `playRate` 微调对齐**（`c = 1/T_cycle`，jog 1.24 Hz；驻留窗 `MM-PHASE-SETTLE-T`=0.40 s）：
```text
r_raw = v_world / v_clip
Δp    = wrap(phase_db − phase_query, −0.5, +0.5)                 # 单位 = 周期
r     = clamp( r_raw + Δp / (MM-PHASE-SETTLE-T · c), 1 ± MM-PLAYRATE-MAX )
若 |Δp| ≤ MM-PHASE-TOL (0.08) → 不施加相位项（防 churn）
```
算例：`Δp`=0.10、jog 下相位项 = `0.10/(0.40×1.24)` = +0.202 → `r` 被 clamp 到 1.12，剩余相位差 0.40 s 内闭合到 ≤ 0.02 周期。硬上限：相位项只吃满 **±`MM-PLAYRATE-MAX` = ±12%**；且仅在未触发 §3.3 重搜时施加——`r_raw` 本身被 clamp 说明速度组选错，应重搜而非硬拉播放速率。
## 7. 程序化 IK
**7.1 两骨解析 IK（髋—膝—踝）**：骨架尺寸由 `CC-STAND-H` 1.78 m 反推写入骨架表——大腿 `l1`=0.44 m、小腿 `l2`=0.42 m、踝高 0.09 m；髋静止高 0.94 m → 站立 `d`=0.85 m。
```ts
export function solveTwoBone(h: Vec3, t: Vec3, pole: Vec3, l1: number, l2: number) {
  const d0 = len(sub(t, h)), dMax = (l1 + l2) * 0.995;         // 0.856 m，留 0.5% 防锁死
  const dMin = Math.abs(l1 - l2) + 1e-3;                      // 0.021 m
  const d = clamp(d0, dMin, dMax), axis = norm(sub(t, h));     // axis: 髋→目标
  const cosA = (l1*l1 + d*d - l2*l2) / (2*l1*d);               // 余弦定理：α = ∠(髋→目标, 髋→膝)
  const a = Math.acos(clamp(cosA, -1, 1));
  const bend = norm(sub(pole, scale(axis, dot(pole, axis))));  // 极向量正交化
  const knee = add(h, add(scale(axis, l1*Math.cos(a)), scale(bend, l1*Math.sin(a))));
  return { knee, reached: d0 <= dMax };
}
```
极向量 `pole = norm(forward + 0.213·side)`，`0.213 = tan(MM-IK-KNEE-SPLAY 12°)`，`side` 左腿 −X、右腿 +X：膝弯方向与大腿朝向解耦 12°，避免极向量与轴共线时膝关节 180° 跳变。自检 `|knee−hip| = l1`（容差 1e-4），见 §9 A9。
**7.2 脚部探针与骨盆下压**：

| 项 | 数值 |
|---|---|
| 每足射线数 | **3**：沿局部 +Z 的 toe `+0.09 m`、center `0.00 m`、heel `−0.07 m`（自踝点偏移） |
| 射线方向 / 长度 | 世界 `(0,−1,0)` / `MM-IK-RAY-LEN`=0.45 m |
| 地面高度 | 3 条命中的**中位数**（取最小值会把脚拉进凹坑）；法线取与中位数同高那条命中面的法线 |
| 未命中处理 | 权重按命中数缩放 1/3、2/3、3/3；全不命中则该脚不加 IK |
| 高度平滑 | `h += (h_raw−h)·(1−e^{−dt/`MM-IK-FOOT-SMOOTH`})`；`dt`=`TM-DT` 16.667 ms、τ=0.12 s → 单帧系数 **0.130**，3τ=0.36 s 收敛 95% |
| 硬贴 | `h_smooth − h_raw > MM-IK-SNAP-DROP`（0.25 m）则直接取 `h_raw`（下坠台阶不应慢落） |
| 骨盆下压 | `drop = clamp(−MM-IK-PELVIS-FRAC·min(0, min(h_L,h_R)), 0, MM-IK-PELVIS-MAX)` = `clamp(−0.5·min(0,min(h_L,h_R)), 0, 0.18)` |
符号约定：`h` = 实际地面高 − 片段期望接触高。`h<0`（地面更低）腿被迫超伸 → 下压骨盆；`h>0` 抬脚即可 → 骨盆不动，故下压只对负半轴生效。上限 0.18 m，超出视为台阶，应由 `CC-STEP-UP` 的迈步/翻越接管。
**7.3 注视 IK**：`w_look = clamp((MM-LOOK-CONE − θ)/MM-LOOK-CONE, 0, 1)² × MM-LOOK-MAX`，`θ` = 目标相对头部朝向夹角。

| θ | 0° | 20° | 40° | 60° | 80°（=`MM-LOOK-CONE`） |
|---|---|---|---|---|---|
| `w_look`（`MM-LOOK-MAX`=0.80） | 0.800 | 0.450 | 0.200 | 0.050 | 0.000 |
附加限制：目标距离 ≤ `MM-LOOK-DIST` 12 m；权重平滑 τ=0.15 s；单帧增量 ≤ 0.08；关节限位 yaw ±70°、pitch −40°…+30°。平方项使权重在锥缘一阶导连续到 0，目标出锥时不「弹回」。
**7.4 手部贴墙 IK 触发条件**：

| 条件 | 阈值 |
|---|---|
| 射线 | 左右肩各 3 条（−60°/0°/+60°，以局部 +Z 为基准，水平面内） |
| 距离 | 最近命中 ≤ `MM-WALL-DIST`=0.55 m |
| 面朝向 | 命中面法线与手部朝向夹角 ≥ 120°（可按压面，排除斜擦面） |
| 状态白名单 | `state ∈ {idle, block, cover_low, cover_high}` |

**8.1 `TM-BUDGET-MM-SEARCH`=1.2 ms 怎么花**：

| 子步骤 | 规模 | 单 actor 耗时（E3） |
|---|---|---|
| 轨迹采样+32 维拼装+归一化 | 5 点采样、32 次除法 | 0.030 ms |

| 约束过滤+选择 | 32 次比较 | 0.005 ms |
| **合计** | | **0.170 ms** |
