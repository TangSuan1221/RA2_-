## 1. 移动模型

### 1.1 期望速度 → 加速度积分 → 位移

阶段 2（03 §2 表第 2 行）内完成，纯函数，不读时钟（不变量 I5）：

```ts
// character/motor.ts —— 阶段 2
export function integrateMotor(m: MotorState, desired: Vec3, dt: number): void {
  const dir = normXZ(desired), sp = dotXZ(m.vel, dir);      // sp = 期望方向的投影速度
  const aMax = (lenXZ(desired) > sp) ? CC_ACCEL : CC_DECEL; // 按模长增/减判定，不按输入方向
  const dSp  = clamp(lenXZ(desired) - sp, -aMax * dt, aMax * dt);
  const k    = Math.max(0, 1 - CC_DECEL * dt / Math.max(sp, 0.01));   // 侧向残余 = 转向惯性
  m.vel = addXZ(m.vel, addXZ(scaleXZ(dir, dSp), scaleXZ(subXZ(m.vel, scaleXZ(dir, sp)), k)));
}
```

**为什么加速慢（`CC-ACCEL` 14.0）、减速快（`CC-DECEL` 22.0，比值 0.636）** —— 三条理由缺一不可：

| # | 理由 | 反证（取反会发生什么） |
|---|---|---|
| 1 | 给 MM 留过渡采样区间：sprint 从 0 加满 24 步（§1.2），walk/jog 片段才有被选中的机会 | 加速也取 22 → 仅 15 步，≥3.35 m/s 前几乎只选冲刺段，起步即冲刺姿态，本质是 F1 |
| 2 | 减速是惩罚，必须短：收招、贴墙、松手都发生在减速段 | 减速取 14 → 松手滑行 0.71→1.12 m，直接违反 §1.3 的 0.12 m 容差 |
| 3 | 冲刺掉头可行性：`CC-TURN-SPRINT` 180 °/s 掉头需 1000 ms | 减速慢则中段位移过大，A9 与 §1.4 掉头规则同时失效 |

单步量（`TM-DT` = 16.667 ms）：加速 **0.2333 m/s/步**，减速 **0.3667 m/s/步**。

### 1.2 速度档位表（`CC-SPD-*` 全量 + 派生量）

| 档位 | 常量 | m/s | 加满步 | 时间 ms | 加速距离 m | 刹停步 | 时间 ms | 刹车距离 m |
|---|---|---|---|---|---|---|---|---|
| 步行 | `CC-SPD-WALK` | 1.55 | 7 | 116.7 | 0.086 | 5 | 83.3 | 0.055 |
| 小跑（默认） | `CC-SPD-JOG` | 3.35 | 15 | 250.0 | 0.400 | 10 | 166.7 | 0.255 |
| 冲刺 | `CC-SPD-SPRINT` | 5.60 | 24 | 400.0 | 1.120 | 16 | 266.7 | 0.713 |
| 蹲行 | `CC-SPD-CROUCH` | 1.05 | 5 | 83.3 | 0.040 | 3 | 50.0 | 0.025 |
| 瞄准前压/后退 | `CC-SPD-AIM-WALK` | 1.35 | 6 | 100.0 | 0.065 | 4 | 66.7 | 0.042 |
| 瞄准侧移 | `CC-SPD-AIM-STRAFE` | 2.20 | 10 | 166.7 | 0.173 | 6 | 100.0 | 0.110 |

派生公式：加满步 `= ceil(v / CC-ACCEL / TM-DT)`，刹停步 `= ceil(v / CC-DECEL / TM-DT)`，距离 `= v²/(2a)`。档位闸门按序短路：`Upper = meleeAction` 或 `combat.locked ≠ null` → 速度由招式 rootMotion 全接管（§2）；`aim` → 前压取 `CC-SPD-AIM-WALK`、纯侧向取 `CC-SPD-AIM-STRAFE`、斜向按 0.5 混合且模长钳到 `CC-SPD-AIM-STRAFE`；`crouch` → `CC-SPD-CROUCH`；`sprint` 且 `‖move‖ ≥ 0.5` 且非 aim → `CC-SPD-SPRINT`；`‖move‖ ≥ 0.5` → `CC-SPD-JOG`；其余按摇杆模长在 0.10→1.0 线性映射到 0→`CC-SPD-JOG`。

### 1.3 停止距离与「松手滑行」允许量

| 档位 | 理论减速位移 m | 允许偏差 | 归零时限 |
|---|---|---|---|
| `CC-SPD-SPRINT` | 0.713 | ≤ **0.12 m** | ≤ 26 步（433 ms），否则判 F1 |
| `CC-SPD-JOG` | 0.255 | ≤ 0.12 m | ≤ 10 步（167 ms） |
| `CC-SPD-WALK` | 0.055 | ≤ 0.06 m | ≤ 5 步（83 ms） |
| `CC-SPD-AIM-STRAFE` | 0.110 | ≤ 0.08 m | ≤ 6 步（100 ms） |

- **判定口径**：`滑行量 = 实际停止位移 − v²/(2·CC-DECEL)`。0.12 m 是**超出理论值的容差**，不是总位移；依据：帧离散残差 ≤ 1 步（0.093 m @sprint）+ `MM-BLEND-T` 0.18 s 惯性化残留 ≈ 0.02 m，上限之和 0.115，取整 0.12。**松手定义**：`‖move‖` 从 ≥0.5 掉到 0 的那一步记为 step 0，到 `speed < 0.10 m/s` 计步；减速段禁止误用 `CC-ACCEL`（`aMax` 由模长增减判定，不由输入方向判定）。

### 1.4 转身角速度三档与「动画转身 vs 程序转身」分工

**唯一写入者规则（F8 的正面修复）**：`transform.yaw` 只有**程序转身**会写；动画转身只改 pose，永不写 yaw。

| 档位 | 常量 | 90° 耗时 | 180° 耗时 | 单步最大转角 | 适用 |
|---|---|---|---|---|---|
| 自由 | `CC-TURN-FREE` 640 °/s | 140.6 ms | 281.3 ms | 10.67° | Lower ∈ idle/walk/jog/crouch |
| 瞄准 | `CC-TURN-AIM` 220 °/s | 409.1 ms | 818.2 ms | 3.67° | `aim` 意图按住 |
| 冲刺 | `CC-TURN-SPRINT` 180 °/s | 500.0 ms | 1000.0 ms | 3.00° | `sprint` 且 `‖v‖ ≥ 4.48` |

分工表（θ_err = 期望 yaw 与当前 yaw 的最短夹角）：

| θ_err | 速度 | 执行者 | 规则 |
|---|---|---|---|
| ≤ 25°（`05-新增-14`） | 任意 | **动画转身** | 程序写 0，靠 `MM-W-HEADING` 惩罚自然选到转向片段；θ_err 持续 > 400 ms 未收敛则降级为程序转身 |

| 任意 | `Upper = meleeAction` | 程序转身上限 0 | yaw 由 rootMotion/锚点接管（§2.3） |

## 2. 根运动消费

### 2.1 三种模式（与 10 章 `moveset.rootMotion.mode` 一一对应）

| mode | 位移来源 | motor 权限 | 典型招式 | 用到的 10 章字段 |
|---|---|---|---|---|
| `inPlace` | 期望速度积分（§1.1） | 全权 | 走/跑/蹲/瞄准/急停/循环步态 | — |
| `rootMotion` | `anim/<clip>.bin` 末尾 `rootDelta`（10 §8） | 只做碰撞修正 + 地面吸附，禁止额外加速 | 翻越/攀爬/闪避/处决演出/受击击退位移 | — |
| `warp` | `(warpTarget 世界锚 − 胶囊位置) × curve(pct)` | 被完全接管，速度归零 | 近战起手贴靠/处决对齐/上下文替换对齐 | `warpTarget`、`maxWarpDist`、`curve` |

`warp` 每步位移 `d = total × curve(pct) × (dt / remainingSec)`，站位点 = 锚点沿目标朝向后退 0.95 m（双人动画常用肩距），单步仍受 `05-新增-12` 0.22 m 钳制。曲线末值 `curve(1.0) = 0.95`（10 §1 示例）意味着到位后余 5%（`maxWarpDist` 1.60 时 0.08 m）由 motor 在收招段补齐——这是设计：留 0.08 m 让目标的小幅移动不至于拉断演出。

### 2.2 MM 根运动与 motor 的冲突仲裁（F1 的正面修复）

同一步只允许一个位移写入者，但 `inPlace` 下 MM 片段根轨迹与 motor 积分会重叠，按速度加权：`d_step = w_mm · clipRootDelta + (1 − w_mm) · motorDelta`。

| 规则 | 内容 |
|---|---|
| R1 | **低速 MM 主导**：`‖v‖ ≤ CC-SPD-WALK` → `w_mm = 1.0`；**高速 motor 主导**：`‖v‖ ≥ CC-SPD-JOG` → `w_mm = 0`；区间内 `w = (CC-SPD-JOG − ‖v‖)/(CC-SPD-JOG − CC-SPD-WALK)` |
| R2 | **交接窗口 120 ms**（`05-新增-13`）：`w_mm` 每步限幅 `Δw ≤ TM-DT/0.120 = 0.139`，0→1 最快 8 步；窗口内禁止反向穿越阈值（迟滞），避免 2.45 m/s 附近抖动 |
| R3 | `mode = rootMotion` 时 `w_mm` 强制 1.0 且 motor 关闭积分；`mode = warp` 时两者皆 0（§2.3 全接管）；总位移再受 `05-新增-12` 钳制，被钳制的步必置 `stuck` 并计入 13 章统计 |

低速必须 MM 主导，因为低速片段的根轨迹编码了真实脚部着地位移，改用 motor 积分会让脚在地上拖（F1）；高速必须 motor 主导，因为碰撞、加速曲线、台阶吸附都要在 motor 侧精确可控，MM 根轨迹是「平均意义上的位移」，撞墙时会穿过。

### 2.3 `warp` 的位移上限与拒绝路径

| 条件 | 结果 |
|---|---|
| `dist ≤ maxWarpDist × 0.80`（默认 1.60 → **1.28 m**） | 正常 warp；留 20% 余量吸收目标移动 |
| `0.80·maxWarpDist < dist ≤ maxWarpDist` | 可执行，但 `curve` 整体按 `dist/maxWarpDist` 缩放，末端余量 > 0.08 m 须由 motor 在收招段补齐 |
| `dist > maxWarpDist` | **拒绝**：`warpTarget = null`、`warpRejected = true`，交 06 §3.4 走接近相（Melee Move） |
| warp 中撞到几何 | 剩余位移丢弃，切回 `inPlace`，**禁止穿墙追锚点**；已损失 > 50% 位移则判招式失效并允许取消（08 章） |

## 3. 胶囊碰撞与移动求解

### 3.1 胶囊扫掠（两球 + 中间梯形，5 条实现要点）

胶囊 = 下球心 `c0 = pos + (0, CC-CAP-RADIUS, 0)` + 上球心 `c1 = pos + (0, H − CC-CAP-RADIUS, 0)`，半径均 `CC-CAP-RADIUS` 0.32，`H ∈ {CC-STAND-H 1.78, CC-CROUCH-H 1.05, 插值中值}`。中间「梯形」= 斜向接触时圆柱侧面形成的截锥投影，离散化为 4 个插值球。

| # | 要点 | 理由 |
|---|---|---|
| 1 | 对 `t ∈ {0, 1/3, 2/3, 1}` 的 4 个插值球做 `three-mesh-bvh` 的 `shapecast`（Sphere），取最小 `t` | 4 段是「不漏检 > 0.08 m 凸起」的最少分段；前提是关卡三角形边长 ≤ 1.0 m（13 章几何预算） |
| 2 | 收集法线夹角 < 60° 的命中面为「平面桶」，逐平面投影后重扫，**最多 3 次迭代** | 3 平面凹角闭包（墙-墙-地）；超过 3 次仍被挡 → `stuck = true`（F2 告警） |
| 3 | **先解水平 xz，再解竖直，最后地面吸附** | 顺序不可反：先解竖直会让台阶探测看到"已抬升"的假状态，导致 F3 间歇失败 |
| 4 | `skin width = 0.005 m` 沿命中法线外推；残留位移沿 **3 个平面的平均法线**投影，不得沿单面法线 | 前者防下一帧同面重复命中与 4 段离散化的微穿透；后者防内角在两墙间来回弹（观感是"卡在缝里抖"） |

### 3.2 沿墙滑动（F2 的正面修复）

```ts
const n = normXZ(hitNormal), vn = dotXZ(v, n);
if (vn < 0) v = subXZ(v, scaleXZ(n, vn));       // 扣除法向分量
v = scaleXZ(v, (vn < 0) ? 0.92 : 1.0);          // 05-新增-01，只衰减切向，竖直不动
```

| 项 | 值 | 说明 |
|---|---|---|
| 摩擦系数 | **0.92 / 逻辑步**（`05-新增-01`） | 半衰期 `ln0.5/ln0.92 = 8.31 步 = 138.5 ms`；过黏调到 0.97（22.8 步），ID 不改 |
| 施加条件 | 仅当输入含压墙分量（`vn < 0`） | 纯平行墙跑**不施摩擦**，所以贴墙横跑不掉速、斜顶墙会黏住——这正是玩家对"墙有摩擦"的直觉 |
| `stuck` 判据 | 连续 5 步位移 < 0.001 m 且 `‖desired‖ > 0.5` | A2 断言直接读此标志 |

### 3.3 台阶处理（F3 的正面修复）

| 阶段 | 动作 | 参数 |
|---|---|---|
| 探测 | 期望方向前 `CC-CAP-RADIUS + 0.10 = 0.42 m` 处，从 `pos + (0, CC-STEP-UP + 0.05, 0)` **向下球扫 0.20 m** | 命中面法线与 Y 夹角 ≤ `CC-SLOPE-MAX` 才是可行走面 |
| 抬升 | `pos.y = hitY`，清空竖直速度 | 瞬时完成，插值会露穿模 |
| 守卫 | 抬升后 **3 步 = 50 ms**（`05-新增-02`）禁止下坠判定与回落 | 修掉"上去了又掉下来"的抖动，与 F3 同一修复 |
| 下台阶 | 脚下 **0.35 m**（`05-新增-03`）内有可行走面 → 吸附；> 0.35 m → 进 `falling`（Lower 不变，由 04 章 `locomotionTag` 切空中变体） | 0.35 = `CC-STEP-UP` × 0.78，上难下易符合人类步态 |
| 边界 | 0.44 m → step；0.46 m → **不得**判 step，进 §4 分类为 vault 候选 | A3/A4 断言对 |

### 3.4 坡度（F4 的正面修复）

`θ = acos(dot(groundNormal, up))`。

| 区间 | 行为 | 速度上限 |
|---|---|---|
| `θ ≤ CC-SLOPE-MAX`（45°） | 完全接地，滑动加速度 **恒为 0** | 档位速度 × 1.0 |
| 45° < θ ≤ `CC-SLOPE-SLIDE`（50°） | 接地、不滑动（静摩擦仍成立） | 档位速度 × `cosθ × 1.15`（45°→0.813，50°→0.739） |
| θ > `CC-SLOPE-SLIDE`（50°） | 沿下坡切向加速滑落 | 不受档位约束，直到接地或坠落 |

滑动加速度（E3，`μ_s = tan(CC-SLOPE-SLIDE) = tan 50° = 1.1918`，`g = 9.81`）：`a_slide = g · (sinθ − μ_s · cosθ)`，方向 = 下坡切向。

| θ | 50° | 55° | 60° | 65° | 70° |
|---|---|---|---|---|---|
| `a_slide` m/s² | 0.00 | 1.33 | 2.65 | 3.95 | 5.22 |

`θ = CC-SLOPE-SLIDE` 处 `a_slide = 0`，与常量表「50° 开始滑落」自洽——这是本公式被要求的唯一自检点（A5）。

### 3.5 角色间推挤（F7 的正面修复）

`d = (r_a + r_b) − |p_b − p_a|`（`r = CC-CAP-RADIUS`，`d ≤ 0` 不处理）；分离速度 `‖v_sep‖ = min(d / TM-DT, 05-新增-04 = 2.2 m/s)`，即每步最多 0.0367 m；质量分配 `w_a = m_b/(m_a+m_b)`，`CC-MASS` 78 双方面 **各 50%**，AI 质量 110 kg（09 章角色表）时玩家侧 0.585 → **封顶 0.50**，超出由 AI 吸收。推挤只产生位置修正，与击退解耦（击退初速另按 `CB-KNOCKBACK-BASE` 以 `CB-KNOCKBACK-MASS-REF` 为参考质量线性缩放）。

**AI 不得把玩家挤进墙角**（三条硬规则，全部可判定）：

| # | 规则 | 判定方法 |
|---|---|---|
| R1 | AI→玩家 的推挤位移占比封顶 **0.50**，无论质量比 | `‖Δp_player‖ / (‖Δp_player‖ + ‖Δp_ai‖) ≤ 0.5001` |
| R2 | **凹角抑制**：玩家胶囊后方 **0.60 m**（`05-新增-05`）内存在夹角 ≥ 90° 的双面几何（两法线 `dot ≤ 0`）时，玩家侧位移**置零**，AI 侧承担 100% | 复用 §4 的后向射线 + 两个侧后射线；A8 |
| R3 | 玩家主动走向 AI 时 AI 侧权重强制 ≥ 0.50（AI 必须让位，不许站桩顶人）；AI 处于 `meleeAction` 或 `combat.locked` 时豁免，此时玩家侧位移置零 | 记录双方位移符号 |

## 4. 环境通行判定

> 高度分层沿用《研究/TLOU-REA-大地图与关卡规范.md》§3.2（该报告自标 E3，本章沿用标注）：`CC-STEP-UP` / `CC-VAULT-MAX` / `CC-CLIMB-MAX` 三个常量即该表取值。

### 4.1 四射线 + 球探针（每次判定 6 个探针，1 步内完成）

| 探针 | 起点（相对胶囊底） | 方向 | 长度 | 用途 |
|---|---|---|---|---|
| R_top | +1.55 m（= `CC-STAND-H` − 0.23） | 前向 yaw | 1.20 m | 上方是否有横向阻挡 → 区分 vault / climb |
| R_chest | +1.05 m（= `CC-CROUCH-H`） | 前向 yaw | 1.20 m | 障碍顶面是否已高于蹲高 |
| R_knee | +0.35 m | 前向 yaw | 1.20 m | 是否只是矮台阶 |
| R_down | +0.02 m，前向 0.55 m 处 | 向下 | 2.40 m | 求落点地面高度差 Δh |
| S_land | 落点正上方 | 球 overlap（r = `CC-CAP-RADIUS`） | — | 落点胶囊可否容纳 |
| S_head | 落点 + `CC-STAND-H` | 球 overlap | — | 落点头顶净空 |

探针频率 = 每 2 步一次（30 Hz），仅当 `‖move‖ > 0.10` 或 `interact` 意图按下时执行；常驻 60 Hz 会撞破 `TM-BUDGET-LOGIC` 中阶段 3 的 0.8 ms 分配（A12）。

### 4.2 高度分类表

| Δh（障碍顶 − 脚底） | 分类 | 触发方式 | 常量 |
|---|---|---|---|
| < 0.45 m | `step` | 无输入，自动抬升（§3.3） | `CC-STEP-UP` |
| 0.45 – 1.20 m | `vault` | `interact` 意图 + 朝向锥通过 | `CC-VAULT-MAX` |
| 1.20 – 2.20 m | `climb` | `interact` 意图 + 双手空闲（非 aim / 非 meleeAction） | `CC-CLIMB-MAX` |
| > 2.20 m | 不可通行 | 不发提示、不进 06 §2 候选（`avail = 0`）；梯子属关卡物件（REA §3.2：2.20–8.00 m） | — |

### 4.3 翻越目标点合法性（4 条全通过才发提示）

| # | 条件 | 判据 |
|---|---|---|
| 1 | 落点可站立 | S_land 无 overlap **且** R_down 命中面夹角 ≤ `CC-SLOPE-MAX`（否则翻到斜坡上滑落） |
| 2 | 落点头顶净空 | S_head 无 overlap；`climb` 豁免（攀爬后接蹲姿），否则翻上去穿模 |
| 3 | **边缘距离** `d_edge ∈ [0.20, 0.40] m`（`05-新增-08`） | 0.20 = 0.625 × `CC-CAP-RADIUS`（胶囊不越过边缘）；0.40 由 `maxWarpDist` 1.60 内可达位移反推 |
| 4 | 竖直余量 | 落点到障碍顶 ≥ 0.05 m，否则落点正压台面，下一帧被 step 再抬一次 |

任一失败 → 不发提示，并把该候选写入 06 §2 的 `avail = 0` 闸门（是闸门不是权重，理由见 06 §2）。

### 4.4 误触发抑制（F6 的正面修复）

| 机制 | 参数 | 说明 |
|---|---|---|
| 朝向锥 | `05-新增-06` = **±40°** | `interact` 意图方向与「障碍面法线反方向」夹角 ≤ 40°；侧向滑过时夹角 ≈ 90° → 全拒 |
| 速度门 | `vault` 要求 `‖v‖ ≥ CC-SPD-WALK × 0.6 = 0.93 m/s` **或** `‖v‖ < 0.10`（原地翻越走 `climb` 变体） | 0.10–0.93 的"半速蹭过去"会让 warp 锚点逐帧跳动，归零到原地分支 |
| 冷却 / 状态门 | `05-新增-07` = **250 ms = 15 步**；同期同一 `obstacleId` 不重复进候选（由 06 §2 的 `id` 去重处理）；`Upper ≠ free`（aim / meleeAction / reload）时不判定 | 翻越落地的 Additive 层与下一次探测混叠会产生"连续翻两次"；interact / 攻击期间手被占 |

## 5. 蹲起与姿态过渡（F5 的正面修复）

| 量 | 蹲 | 站 | 插值 |
|---|---|---|---|
| 胶囊总高 | `CC-CROUCH-H` 1.05 | `CC-STAND-H` 1.78 | **180 ms**（`05-新增-09`）= 11 步 = 183.3 ms，线性 |
| 视点高 | `CC-CROUCH-EYE-H` 0.92 | `CC-EYE-H` 1.62 | 同曲线同长 |
| 相机枢轴 | 1.58 × 0.92/1.62 = **0.897** | `CAM-PIVOT-H` 1.58 | 同曲线，**只读**；下限 `05-新增-11` = 0.85 m |
| 每步高度增量 | — | — | (1.78 − 1.05)/11 = **0.0664 m/步** |

**头顶检测**：球探针 `r = CC-CAP-RADIUS` 位于 `pos + (0, h_cur + r, 0)`，向上扫 `(CC-STAND-H − h_cur)`。

| 结果 | 行为 |
|---|---|
| 无命中 | 正常插值起身 |
| 命中 | **阻断**：保持蹲姿、`crouchBlocked = true`、`eyeHeight` 冻结在当前值（**不回弹**，回弹会让视点上下抖） |
| 重试 | 每 6 步 = 100 ms（`05-新增-10`）重试一次；`eyeHeight` 不得越过 `blockedY − CC-CAP-RADIUS`（天花板 1.60 m 时封顶 1.28 m，A6） |
| 提示 | 由 13 章 debug overlay 读取 `crouchBlocked` 渲染；**本章不改 03 §4.5 的 `GameEvent` 联合类型**（新增事件类型属 13 章扩展） |

**谁驱动谁（必须写死）：Character → Camera，单向**。① Character 在阶段 2–3 写 `MotorState.eyeHeight` 与 `posturePct`；② 07 章枢轴高 `= CAM-PIVOT-H × (eyeHeight / CC-EYE-H)`，**不再对枢轴施加 `CAM-POS-LERP` 0.18/帧**——双重阻尼会让枢轴滞后于视点，产生"头已抬起但镜头还低着"的错位；③ 相机**不回写**角色任何字段，任何"相机把玩家顶出去"的实现都是错的；④ 蹲姿是比例缩放不是常量替换：0.897/1.58 = 0.92/1.62 = **0.568**，保证过肩构图等比收缩。

## 6. 面向 MM / IK 的接口

阶段 3 结束时（用本步**最终** transform 重采样一次）向动画层输出以下结构。`desiredSpeed` / `velocity` / `heading` / `locomotionTag` **字段名与 03 §4.2 `MMQuery` 逐字相同**，可直接拼进查询；其余字段不进特征向量，只给 `anim/ik.ts` 与 `anim/montage.ts`。

```ts
// character/motor.ts —— 阶段 3 结束时输出
export interface FootProbe { hit: boolean; pos: Vec3; normal: Vec3; dist: number; weight: number; }
export interface MotionBridge {
  // —— 与 03 §4.2 MMQuery 同名，可直接拼进查询 ——
  desiredSpeed: number; velocity: Float32Array; heading: Float32Array; locomotionTag: number;
  //  heading = [sin(yaw), cos(yaw)]，0° = +Z（10 §0）
  //  locomotionTag: 0=idle 1=walk 2=jog 3=sprint 4=crouch 5=aimWalk 6=aimStrafe
  // —— 本章新增，不进特征向量，只给 anim/ik.ts 与 anim/montage.ts ——
  groundNormal: Float32Array;   // [nx,ny,nz]；离地固定 [0,1,0]
  footProbe: FootProbe[];       // 长度恒为 4，见下表
  warpTarget: Vec3 | null;      // null = 本步无 warp（§2.3 拒绝时亦为 null）
  posturePct: number; eyeHeight: number;   // 0 = 全蹲 / 供 07 章算枢轴（§5）
  stuck: boolean;               // 供 13 章统计
}
```

`footProbe` 四项固定顺序（采样频率 = 每逻辑步 1 次，IK 在阶段 9 读本步快照，与阶段 3 同源无错位）：

| idx | 骨骼 | 采样点 | 射线长 | IK 权重上下限 |
|---|---|---|---|---|
| 0 | `foot_l` | 踝关节世界位置 | 向下 0.60 m | 0.0 – 1.0 |
| 1 | `ball_l` | 前脚掌 | 向下 0.60 m | 0.0 – 0.80 |
| 2 | `foot_r` | 踝关节世界位置 | 向下 0.60 m | 0.0 – 1.0 |
| 3 | `ball_r` | 前脚掌 | 向下 0.60 m | 0.0 – 0.80 |

`weight` 由 `anim/ik.ts` 按 `dist` 计算（抬脚随 `dist` 增大，压脚随 `dist` 减小），Character 只保证 `hit/pos/normal/dist` 正确。0.60 m 射线长依据：`CC-STEP-UP` 0.45 + 0.15 容差；超过 0.60 m 的落差一律交 Lower 的 `falling` 分支，不做 IK（做了就是"橡皮腿"）。
